Bun 1.4.3 内置 bun check 类型检查

Bun 官方 10 月 10 日发布 1.4.3，主打内置 TypeScript 类型检查器 `bun check`，称通过 tsc 7.0.2 全量一致性测试，并在多项目上快于 tsc 数倍。

2026-10-11 语言 / 运行时 / 框架

JavaScript 运行时 Bun 于 10 月 10 日发布 v1.4.3。博客头条是 `bun check`：把 TypeScript 类型检查直接做进 Bun，读取项目 `tsconfig.json`，报错形态对齐 `tsc`，并可吃满多核。官方给出的对照表显示，在 VS Code 源码、Next.js、mikro-orm 等仓库上，相对 TypeScript 7.0.2 的 `tsc` 约有 3–6.4 倍耗时优势，内存占用亦明显更低。团队称其通过 tsc 7.0.2 全部一致性测试（错误、类型、符号、声明、模块解析等合计五万余项）。

配套开关把类型检查嵌进日常命令：`bun run --check`、`bun test --check`、`bun build --check`（以及 `Bun.build({ check: true })`）都会在执行/打包前先过类型关，有错则不跑、不写出产物。官方强调：它只做检查，不发射 JS 或 `.d.ts`，也不替代编辑器里的语言服务——IDE 仍用 TypeScript。

同版还有 `Bun.FetchSession`（独立 TLS/代理/连接池）、实验性 `Bun.ModuleGraph`（同进程多实例隔离模块状态）、空闲时 CPU 占用下降、大响应在 `node:http` 路径上的吞吐改进，以及一批针对 CVE 与 Node 兼容性的加固。对「语言/运行时」栏目而言，真正改变开发者日常的是：类型检查从「另开一条 tsc 流水线」变成「Bun 自带的一道闸」。

边界：性能数字来自官方博客在苹果硅机器上的自测；一致性测试通过不等于所有真实仓库零差异（官方亦公开了少数边界 mismatch 与模糊测试未对齐项）。晨报 Python 3.15.0 不在此重复。
