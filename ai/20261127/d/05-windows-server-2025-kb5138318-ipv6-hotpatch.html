微软为 Windows Server 2025 再发不重启热补丁，修复会致系统停止的 IPv6 路由故障

微软 11 月 25 日发布带外热补丁 KB5138318，修复 11 月安全热补丁 KB5131077 引入的问题：在启用路由器通告并收到有时限 IPv6 路由的 Windows Server 2025 上，路由计时到期时可能出现 0x139 停止错误。官方写明安装后无需重启。《注册》11 月 26 日作了报道。

2026-11-27 操作系统与桌面

微软在 11 月 25 日发布了带外热补丁 KB5138318（操作系统内部版本 26100.33732），用于修复同月安全热补丁 KB5131077 带来的故障。官方说明写明：部分启用了路由器通告（Router Advertisement）、并且会收到有时限 IPv6 路由的 Windows Server 2025 设备，在路由计时到期时可能意外停止，错误代码为 0x139（KERNEL_SECURITY_CHECK_FAILURE）。这不是定期安全更新里的新漏洞修复，而是对上一个热补丁副作用的紧急更正，安装后立即生效，不必重启。

《注册》11 月 26 日报道了同一份更新。文章解释，0x139 表示内核发现关键数据结构被破坏后主动停机；微软已经定位到触发条件是路由计时到期，但还没有说明底层代码究竟错在哪里。对管理员来说，热补丁的卖点本来就是少重启、少中断，可一旦热补丁自己把机器打停，这个优点就打了折扣。

官方支持页把适用范围写为 Windows Server 2025 Datacenter: Azure Edition 的热补丁通道。安装前需要先具备基准更新 KB5126646，以及版本不低于 26100.33634 的服务堆栈更新；这次包里也会带上较新的服务堆栈更新 KB5131079。已经装过此前更新的设备，只会再下载其中的新增部分。微软目前未公布已知问题。获取途径包括 Windows Update、Microsoft Update Catalog 和 WSUS，官方称符合条件的设备会从 Windows 更新自动安装。

《注册》还提到，近几个月 Windows Server 更新多次在正式补丁之后再出带外修复，这次又是用新的热补丁去修补旧热补丁。资产管理公司 Lansweeper 的监测数据显示，Windows Server 2025 在其统计的服务器里约占 7%，仍远低于 Server 2022 和 2019；真正会碰到这次故障的，只是已经安装了受影响热补丁、并且采用上述 IPv6 配置的那一部分系统。管理员若走的是 Azure Edition 热补丁通道，应确认 KB5138318 已经到位；其他版本是否以同一方式提供这份修复，应以微软支持页和更新目录为准，不宜自行扩大适用范围。

若要核对自己是否已具备安装条件，官方建议在提升权限的命令提示符里查看服务堆栈包版本，确认达到 26100.33634 或更高，并先装好基准更新 KB5126646。这次故障只在特定网络条件下出现，并非所有装过 11 月热补丁的服务器都会停机；但一旦触发，表现就是整机停止，而不是一条可以忽略的日志。因此，走热补丁通道的管理员应把这次带外更新视为优先项，而不是等到下一次定期补丁再处理。

交叉核对

  • 多方一致：微软支持页和《注册》都确认，KB5138318 用于修复 KB5131077 之后、在启用路由器通告并收到有时限 IPv6 路由时可能出现的 0x139 停止错误；更新于 11 月 25 日发布，安装后无需重启。
  • 范围需按官方页面理解：支持页写明适用于 Windows Server 2025 Datacenter: Azure Edition 热补丁通道，并列出基准更新和服务堆栈更新前提。《注册》行文较笼统地写作 Windows Server 2025，本期以官方适用范围为准。
  • 未说明：微软尚未解释导致数据结构被破坏的具体代码缺陷；也未公布受影响设备数量。
