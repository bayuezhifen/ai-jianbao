Hugging Face 提 Transformers MIC：缩模型固件在 PR 上抓行为回归

Hugging Face 11 月 3 日博文提出 Model Integration Contracts（MIC）：为架构固化「缩小版固件 + 可运行用法路径 + 人工审过的输出基线」，在廉价 CPU 上于 PR 阶段做行为回归；起因包括 UMT5 在启用 SDPA 后静默「偷看未来 token」近两月才被发现。

2026-11-04 语言 / 运行时 / 框架

Transformers 库维护者 Tarek Ziadé 写道：2026 年 7 月 30 日为 T5 打开 PyTorch SDPA 时，连带让 UMT5 解码器能注意到未来 token；训练时等于偷看答案，进程不崩，漏洞在 main 上留了近两个月。事后用缩小版 UMT5 固件在 CPU 上重放，每个引入提交都能打出偏离基线的损失与 log-prob。

MIC 提案把这类检查标准化为三件套：从真实 checkpoint 配置缩出来的 fixture（层数/宽度变小但保留关键层类型，分词器与处理器原样拷贝）、一段用户真实会跑的 Markdown 用法（生成、训练步等）、以及人工审过的期望输出。合约在「架构 + 用法路径」粒度生效，兼容 checkpoint 可共享固件、各自保留基线。固件发在 huggingface-mic，fleet 数据集钉死版本与依赖，便于复现。

缩小配方现分四步：缩配置并保留混合注意力/MoE 等层种；预处理文件字节级保留；随机或「过拟合」少量样本以增强灵敏度；冻结并人工审基线。Llama 4 Scout 示例称千亿参数可缩到约数千万级仍保留关键结构。CLI `tmic` 可本地起草、构建、记录基线；大模型只负责草稿，基线变更须人审。

截至 11 月 1 日，Transformers CI 里的 MIC 任务「报失败但不阻断 PR」——是否改成硬门禁，还要看真实缺陷捕获率、误报与基线维护成本。官方也承认：有的缺陷（如 Whisper 辅助解码）只有全尺寸权重才暴露，固件不能替代夜间全量 GPU 集成测试。

对开源 ML 栈，这是把「行为契约」前移到 PR 的一次工程化尝试，和传统单测、全尺寸集成测试互补。是否在社区铺开，取决于覆盖率与维护负担。本窗晨报未收，午报按框架工具热点补入。
