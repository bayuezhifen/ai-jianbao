DeepSeek 公布 Super-agent 架构：双层调度 + 事件驱动，并开源研究原型

10 月 31 日晚，DeepSeek Harness 团队发表《Super-agent 设计探索》技术长文，并同日在 GitHub 开源 MIT 许可的 dsh-superagent-prototype；官方明确其为研究原型，不等于正式产品，也不等同内部系统。

2026-11-01 行业

据第一财经报道，DeepSeek Harness 团队于 10 月 31 日晚在官方公众号发布《Super-agent 设计探索：迈向更自主的 Agent 系统》。文章指出，模型单任务能力增强后，瓶颈正从「会不会做」转向「人的注意力够不够」：现有以单一会话为单位的 Agent，很难在多任务与团队协作规模上支撑持续在线的个人助手形态。

团队把目标形态称为 Super-agent，并概括四个特征：跨信道保持连续上下文、能并行推进互不干扰的多任务、能主动响应环境事件、异常时可自愈并长期在线。支撑框架包括五块：Router/Worker 双层架构、事件驱动、异步多信道交互、存算分离，以及系统外独立的 Watchdog。Router 只负责对外交互与任务分派，Worker 在隔离会话里执行具体工作；群聊消息、代码评审、CI 结果等被当作 Trigger，经过程序快筛与模型慢判后再路由。

文章称，基于该思路的内部实例已在持续运行，日常参与问题复现与修复、代码审查响应以及 Harness 自身迭代；当成员在群聊反馈缺陷时，即便无人主动 @，系统也可能在后台尝试复现并寻找修复方案。智东西同日跟进称，初步合成负载实验里，Super-agent 任务完成时间的中位数与 95 分位分别约 12.4 分钟与 15.7 分钟，显著快于带 Subagent 工具的单会话方案；但实验环境简化，不能当作正式产品结论。

同日开源的 deepseek-ai/dsh-superagent-prototype 以 MIT 许可发布。README 写明：这是研究原型、仅供参考，不是官方 DeepSeek 产品；代码为适配公开发布做过改动，与内部版本及长文描述并不完全一致；部分文中方向仍属未来规划、原型未实现。该原型面向单个 GitHub 仓库，可监听 GitHub 与可选的飞书，按授权规则开工作项并在独立会话中推进，最终以拉取请求等形式回原对话。读新闻时宜把「架构探索 + 研究开源」与「正式产品上线」分开，避免把原型当成现成可用的商用助手。
