Usage and Cost Analytics API 进 beta：按模型、工作区、密钥汇总用量与费用

Anthropic 平台发布说明记载：10 月 29 日推出 Usage and Cost Analytics API（beta），为 Claude Console 与 Claude Enterprise 组织提供按维度汇总的用量与费用查询；旧 Usage and Cost API 改标为遗留接口但仍继续支持。

2026-10-30 Claude / Anthropic

Claude 平台发布说明写到，Usage and Cost Analytics API 以 beta 头 `analytics-usage-cost-2026-08-24` 开放，路径包括 `/v1/organizations/analytics/usage` 与 `/v1/organizations/analytics/cost`，面向 Claude Console 与 Claude Enterprise 组织，可按模型、工作区、API 密钥以及背后的用户或服务账号等维度过滤、分组，查看 token 用量与费用。

同一天说明把既有 Usage and Cost API，以及 Claude Enterprise Analytics API 里若干 `usage_report` / `cost_report` 类端点标成遗留（legacy），并表示短期内仍支持，同时给出迁移指引。对财务与平台团队来说，这意味着「报表」从偏一次性导出，往可脚本化、可按组织维度切片的分析接口靠拢，方便对账、分摊与异常用量巡检。

背景上，本周稍早 Messages / Token Counting 请求体上限已从 32 MB 提到 128 MB，主要缓解截图、PDF 等体积敏感工作负载；那是 10 月 28 日条目，本条不展开。昨午已收 Claude for Legal 的 Artifacts 画廊与企业侧智能报告等产品向更新，本窗不回炒，只补平台侧分析 API。

边界：beta 头与字段集合仍可能变；零留存（ZDR）等特殊合约流量是否完整进入分析维度，要以文档与合同为准。印度今日科技稿热议的「self-assessment」官方长文日期为 10 月 16 日，不纳入本窗主条。

  • 分歧：媒体偶发把「请求体 128 MB」与 Analytics API 捆成一条产品发布，官方是分日条目。
  • 待确认：GA 时间表；Enterprise 与 Console 在维度覆盖上是否完全对齐。
