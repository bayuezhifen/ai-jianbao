VS Code 1.139：远程 SSH/Tunnel/WSL 上可在项目 Dev Container 内跑 Agent Host

微软官方更新说明：VS Code 1.139（2026-09-23）把 Dev Container 会话从本地扩展到 SSH、Tunnel、WSL 上的远程项目，可在 Agents 窗口选用「Use Dev Container」；特性实验、渐进推送。

2026-09-25 开发者工具

VS Code 1.139 稳定版于 9 月 23 日发布。官方更新页把「在远程主机的项目 Dev Container 里跑 agent 会话」列为亮点：开发者可在 Agents 窗口对符合条件的远程文件夹选择 Use Dev Container，让 Agent Host 进入容器内的工具链与依赖，而不必把整套环境复制到笔记本或裸远程主机。

启用条件包括：远程机已装并运行 Docker、PATH 上有 Docker CLI、项目含支持的 .devcontainer 配置，以及打开设置 chat.agentHost.devContainer.enabled（渐进推送期间可能需手动打开）。官方注明目前不能与 New Worktree 组合使用。Techgenyz 等二次报道补充：Agents 窗口仍留在本机，容器内跑的是 Agent Host；并提醒匿名 Dev Tunnel 在自动批准开启时风险更大，应要求 GitHub/微软账户鉴权——这与官方安全提示同向。

同版本还改进大量会话列表的加载：用中央轻量目录代替每次打开全部会话库。微软在约 645 个会话的测试里给出约 12×（首次列表）与约 4×（刷新）的数量级；会话少时体感会弱很多。另有 Compact View、空分组过滤、就地重命名等体验改动。
