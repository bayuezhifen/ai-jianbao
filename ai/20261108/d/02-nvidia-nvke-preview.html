英伟达预览开源 NVKE：让 GPU 机房在自有硬件上提供托管 Kubernetes

德国 heise 11 月 7 日报道，英伟达在 GitHub 上预览了 NVIDIA Kubernetes Engine（NVKE）：机房运营商可在自有 GPU 裸金属上按需开出相互隔离的 Kubernetes 集群。官方文档同时标明：预览阶段，不建议用于生产。

2026-11-07 英伟达 / NVIDIA

heise 于 11 月 7 日中欧时间上午报道，英伟达公开了名为 NVKE（NVIDIA Kubernetes Engine）的开源预览：目标用户是自己运营 GPU 数据中心、希望向客户提供类似云上托管 Kubernetes 的厂商，尤其是英伟达云合作伙伴（NVIDIA Cloud Partners）。官方文档把 NVKE 写成「AI 工厂」软件栈 DSX OS 里的 Kubernetes 管理层——运营商通过 API 提出开集群的请求，NVKE 负责在自有英伟达 GPU 基础设施上准备裸金属节点、组建集群，并驱动节点池扩缩、升级 Kubernetes、替换节点和证书续期。

架构上，一套 NVKE 安装对应机房里的一批工作负载集群。先用命令行工具 nvkectl 在准备好的节点上引导出一个管理集群，再在其上安装管理面；之后每个客户集群拥有自己的控制面、etcd 和节点池。默认通过英伟达基础设施控制器 NICo（经 Cluster API 提供方 CAPNICo）完成机器准备，节点上的 GPU 驱动、Container Toolkit 与 device plugin 仍由 GPU Operator 安装。新集群默认使用 OVN-Kubernetes 作为网络插件；官方文档写明本预览把 Kubernetes 版本钉在 1.36.3。代码与配套构建系统 NVKR 均采用 Apache 2.0 许可，并欢迎外部贡献。仓库路径为 dsx-ai-factory/nvke，文档站点在 docs.nvidia.com/nvke。

预览限制写得很直白，不应被读成「已经能当托管云来卖」。英伟达明确不建议把 NVKE 用于生产，接口、配置和行为都可能在版本之间变化。安装完成后，管理面 API 默认在每个管理节点的 30080 端口提供未加密 HTTP，认证默认关闭；即便后来打开基于身份提供方 JWT 的认证，预览版也没有授权分层——任何被放行的调用者都能创建或删除所有工作负载集群。管理集群不能自我升级、扩容或替换节点，也没有把管理面迁到新版本、以及备份/恢复管理集群状态的正式流程。全盘加密镜像被标明仅供评估：同一镜像构建出的节点共享卷密钥，不能当作静态数据保护。

heise 还提到本地试用：用模拟的 NICo 在一台 Linux 机器上把工作负载节点起成 Docker 容器，官方要求至少 6 个 CPU、12 GB 可用内存、100 GB 磁盘，并支持虚拟 TPM；macOS 上可放进 Colima 虚拟机。英伟达没有宣布正式生产版时间表。官方文档另称，CNCF 已认证 NVKE 拉起的是符合上游一致性的 Kubernetes 集群，本条把它记为文档中的自我表述，未独立复核认证条目。不回炒昨晨已报的先进封装注资传闻与入股 Naver。

交叉核对

  • 多方一致：heise 报道与英伟达官方文档均确认 NVKE 为开源预览，面向自有 GPU 裸金属上的托管 Kubernetes，默认经 NICo 准备机器，并用 nvkectl / API 管理集群。
  • 多方一致：预览不建议用于生产；管理面 API 默认明文 HTTP，且缺少细粒度授权。
  • 待确认：生产就绪时间表官方未宣布；文档中关于 CNCF 一致性认证的表述未见本窗口独立复核。
