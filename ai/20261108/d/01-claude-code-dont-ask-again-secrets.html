Claude Code「不再询问」会把口令写进项目文件，公开仓库里已出现一千余份

The Hacker News 与 iTWire 11月7日跟进 Apiiro 的研究：勾选「是，并且不再询问」后，完整命令（含明文口令或密钥）可能被写入 .claude/settings.local.json；公开 GitHub 上已发现 1122 份含疑似密钥的副本。

2026-11-07 Claude / Anthropic

本窗口 The Hacker News 与澳大利亚 iTWire 于 11 月 7 日报道了软件安全公司 Apiiro 的调查。研究由 Shmulik Cohen 与 Matan Giladi 署名，iTWire 写明正文发布于 11 月 5 日，数据采集窗口为 11 月 1 日至 3 日；周末两家安全媒体把它写成了面向开发者的提醒，而不是厂商新品通告。核心现象并不复杂：Claude Code 默认会在执行多数 shell 命令前征求许可；若用户选择「是，并且不再询问」，工具会把一条允许规则写进项目目录里的 .claude/settings.local.json。规则有时是通配模式，有时是当时屏幕上那条完整命令——后一种情况下，命令里的数据库口令、API 密钥或令牌会以明文一起留下来。

Apiiro 在公开 GitHub 上统计到 104185 份该本地设置文件，分布在 103617 个仓库中，其中约 1.1%、即 1122 份被判定至少含有一枚密钥，合计 1379 个不同值。把 git 历史、有意提交的共享文件 .claude/settings.json 以及智能体对话记录一并算上，他们给出的更大口径是 1994 个仓库里的 2539 枚密钥。分类举例包括 379 个可直连数据库的口令、43 组指向公网服务器的 SSH 登录信息、42 枚 GitHub/GitLab/npm 令牌，以及 23 枚 AWS 密钥；文件归属涉及 63 个组织。研究方强调他们没有实际尝试登录，因此这些数字描述的是「看起来像密钥的暴露」，不能等同于已被盗用或目前仍有效；他们称本周早些时候通知过受影响机构，其中一家确认当时密钥仍可用。

Anthropic 并没有在同一窗口发布官方说明。两篇报道都引用了 Claude Code 自己的权限文档：该本地文件本意是个人设置，工具第一次在 git 仓库里写入时，会尝试把它加入当前开发者机器上的全局 git excludes。这层保护只跟着「这一台电脑上的这个人」，不会写进项目自己的 .gitignore，对已经入库的文件也不生效。研究者在可追溯的 1105 个仓库里，看到 539 个仓库有以 Claude 为共同作者的提交改动了该文件，他们据此认为工具常常会自己把文件提交上去；这并不能证明每一枚密钥都是模型「主动泄漏」的。另外，常见密钥扫描器对「写在命令行里的普通口令」并不敏感：在这 1122 份文件上，gitleaks 标出 564 份、TruffleHog 标出 643 份，两家都没标到的还有 215 份。

操作建议停留在处置层，而不是去复现写入过程：先在本组织的 GitHub 与 git 历史里检索上述文件名，把文件里出现过的口令、令牌、密钥全部轮换，再从版本库取消跟踪并写入项目自己的忽略规则。只删当前文件不够，因为旧提交、分叉和别人的克隆里仍可能留着副本；研究者还统计到 509 个仓库的旧版本里另有 734 枚已不在当前文件中的密钥，以及 74 个源仓库的 211 个分叉带着同样内容。审批时尽量批「模式」而不是整条带密命令，并把秘密放进密钥管理器或运行时变量，避免明文出现在命令文本里。需要说明的是，Apiiro 本身销售应用与智能体安全产品，计数方法含内部大模型复核，外媒也提醒读者把总量当作该公司的研究发现，而不是第三方复验结论。本条不提供可被仿用的检索利用步骤。

交叉核对

  • 多方一致：The Hacker News 与 iTWire 均确认机制来自「是，并且不再询问」把完整命令写入 .claude/settings.local.json，并转述 Apiiro 的 1122 份公开副本、1379 个不同密钥等口径。
  • 多方一致：两家都写明保护依赖开发者本机的全局 git excludes，而不是项目自带的 .gitignore；建议先轮换再清理历史。
  • 分歧/待确认：iTWire 记研究正文发布于 11 月 5 日，The Hacker News 11 月 7 日稿写「Apiiro 昨天表示」；原始采集在 11 月 1–3 日。密钥是否仍有效、是否已被滥用，研究方未做登录验证。
  • 利益披露：Apiiro 销售相关安全产品；Anthropic 本窗口无官方回应。
