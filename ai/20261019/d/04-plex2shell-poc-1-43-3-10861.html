漏洞与勒索

Plex2Shell：公开 PoC 后蜜罐被打，植入挖矿与住宅代理；请升至 1.43.3.10861+

研究者 10/16 公开利用链后，10/17 起有蜜罐遭未授权接管。影响 1.43.3.10861 之前版本；当前建议升到 1.43.4.10903，并检查 Codecs 与异常外连。

2026-10-19 漏洞与勒索

晨报漏洞栏写「无本窗新增 KEV」，但漏掉了正被社区热传的 Plex Media Server 利用链「Plex2Shell」。午后补录：研究者 ZM 于 10 月 16 日公开 write-up 与 PoC，将 CVE-2026-96652/96654/96655/96656 串成无需登录的远程代码执行；10 月 17 日起，BoredHackerBlog 的脆弱蜜罐观察到真实利用，载荷包括 XMRig 门罗币挖矿程序，随后还出现名为 myawesomeproxy 的住宅代理工具。

利用大致路径是：借 /player/timeline 等接口做回环 SSRF，从仅本机可访问的插件接口偷出管理员令牌，再改写转码相关配置，把恶意库丢进 Codecs 目录，在下一次转码时以 Plex 用户身份执行。单条 CVE 的 CVSS 并不都「看起来很吓人」，但链式组合后对暴露在公网 32400 端口的家庭/NAS 实例足够致命。

修复线要写清楚：必须升到 1.43.3.10861 或更高；「1.43.3」字样不够，因为 1.43.3.10828 仍属受影响。社区与汇总页目前多推荐直接升到公开版 1.43.4.10903。Plex 早在 9 月发过「请更新」公告，但细节与 CVE 映射滞后；截至整理时，相关 CVE 尚未进入 CISA KEV。

处置建议（面向自建用户，而非教人攻击）：核对服务器版本；更新后不需要远程访问就关掉 Remote Access 与 32400 端口映射；检查 Codecs 目录异常文件、TranscoderH264Options 是否含可疑参数、是否有 xmrig / 陌生子进程与异常上行流量；轮换 Plex 账号密码并启用两步验证。Docker/Unraid 用户注意镜像标签是否钉死旧版。

与昨午 OpenCode Console 密钥事件分开：那是第三方 API 密钥暴露；本条是媒体服务器远程接管。两者都提醒「家用/开发者常开的高权限软件」一旦暴露公网，补丁窗口可以短到「PoC 次日就有蜜罐中招」。

交叉核对

  • 多方一致：PoC 于 10/16 公开；10/17 起有蜜罐利用报告；修复门槛为 1.43.3.10861+；出现挖矿与代理类载荷。
  • 分歧：大规模「在野感染数量」尚无权威统计；个别社媒把时间线写成「先在野后 PoC」，与公开时间线相反。
  • 待确认：是否进入 KEV、厂商是否对仍脆弱实例主动通知、代理载荷后续用途。
