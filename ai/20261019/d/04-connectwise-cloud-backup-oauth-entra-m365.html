ConnectWise Cloud Backup 应用身份泄露：攻击者借 OAuth 打进客户 Entra/M365

厂商确认 Cloud Backup（原 SkyKick）应用身份遭未授权访问；Huntress 观察到约千个租户出现相关登录、三百余次成功。10 月 18 日服务仍停，并连带暂停 SaaS Security 与 Cloud Management。

2026-10-19 身份与访问

这是一条昨午简报漏收、今晨补录的供应链身份事件。ConnectWise 在信任中心公告中称：Cloud Backup（原 SkyKick）环境中的应用身份遭未授权访问；为阻断风险，已停用相关应用连接并暂停 Cloud Backup。因 SaaS Security、Cloud Management 与备份产品集成，10 月 18 日更新中进一步说明这两项服务也「出于谨慎」一并暂停。公司称截至更新时，未见备份归档本身被篡改或读取的证据，但明确区分：归档安全不等于客户现网 Microsoft 365 租户未被侵入。

攻击路径的核心是「厂商应用机密/证书 → 以已获授权的服务主体登录客户租户」。BleepingComputer、Huntress、Microsoft 威胁情报侧描述一致：攻击者持有 ConnectWise 侧凭证后，可在客户已同意的权限范围内读写邮件、OneDrive/SharePoint、Teams 等，且属于应用身份登录，终端用户 MFA 拦不住。公开 IOC 多次指向 144.172.64.128 等地址，以及 Cloud Backup 应用 ID 506e08f9-6e9a-4da4-942b-a099a03644ae 等一串 ConnectWise/SkyKick 相关企业应用。

Huntress 后续更新称，与指标 IP 相关的 Entra 租户登录约近千个，其中成功超过三百；并在个别租户看到 ConnectWise Cloud Management（Teams）应用给自己授予全局管理员、再向其他应用（含安全厂商自身应用）写入新机密等持久化动作。10 月 18 日 18:45 UTC 左右的厂商更新补充了更多调查 IOC，并要求合作伙伴按技术排查指南审查应用身份、登录与审计、凭据、角色与邮箱变更；同时提醒：禁用应用不会自动清掉攻击者已经写入租户的其他机密，已签发令牌也可能用到过期。

对 MSP 尤其刺痛——一家备份厂商的共享应用身份，理论上能覆盖其所有完成同意的客户租户；一旦机密外流，就是「一钥多门」。条件访问若把备份应用排除在地理位置或风险策略之外，攻击者基础设施更容易直达。为何放在「身份与访问」而非单纯漏洞栏：公开材料强调的是 OAuth/服务主体与厂商机密失守，而不是某一 CVE 编号的远程代码执行。

本窗无新的 CISA KEV 录入与之直接对应；OpenCode 密钥事件昨午已收，不混写。管理员应按 ConnectWise/Huntress 清单禁用相关企业应用、审查 10 月 13 日以来新增的客户端机密与证书，并在厂商确认轮换完成前不要重新启用。简报只陈述已交叉核对的事实与处置建议，不对「是否国家级攻击」作无来源猜测。

交叉核对

  • 多方一致：ConnectWise 公告承认应用身份未授权访问并暂停服务；Huntress 与 BleepingComputer 交叉描述同一 IP/应用 ID 与 Entra 服务主体滥用模式；Microsoft 亦定性为活跃供应链攻击。
  • 分歧：成功入侵租户数量随时间上调（早期百余 → 后续三百+成功/近千出现登录），以厂商与 Huntress 最新更新为准；备份归档是否被读，厂商称暂无证据。
  • 待确认：厂商机密最初如何泄露；全面恢复服务的时间表；受影响租户是否发生大规模数据外带。
