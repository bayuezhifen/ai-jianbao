VS Code 1.140：Copilot harness、多文件夹会话与 HydraFusion 研究预览

微软 9 月 30 日发布 Visual Studio Code 1.140 稳定版，强化智能体工作流：引入与 Copilot CLI／独立应用一致的 Copilot harness，实验性支持多文件夹会话与远程主机委派；GitHub 同步把 HydraFusion 多模型编排研究预览带进编辑器与 Copilot 应用。

2026-10-01 开发者工具

官方更新说明把 1.140 的重心写在「智能体怎么干活」而不是主题皮肤。Copilot harness 基于 Copilot SDK，目标是与 GitHub Copilot 独立应用、CLI 共用同一套智能体运行时；会话跑在基于 Agent Host Protocol 的独立主机进程里，多个 VS Code 窗口可接回同一会话。文档也提醒：共享运行时不等于设置与工具集完全同步，内置／扩展工具可用性仍可能不同。

实验能力两条最实用。一是多文件夹会话：同一会话里每个子聊天可绑不同仓库或 worktree，终端、任务、改动与 PR 按文件夹隔离，适合跨仓功能或并行试方案；默认关闭，需在用户级 settings.json 打开对应 harness 的 multiRoot 开关。二是远程委派：智能体可列出已连接主机，按操作系统、内存、逻辑 CPU、模型可用性等条件建远程会话，并回传状态——不自动克隆源工作区，审批规则仍在。

HydraFusion 同日由 GitHub Changelog 宣布进入 VS Code（需 1.140+）与 Copilot 应用：它不是单一模型，而是按任务选「单模型／级联升级／跨家族批判再改一稿」三种工作流。与 Auto「每请求选一个模型」不同，HydraFusion 把工作流选择也当成优化问题。面向 Pro／Pro+／Business／Enterprise；组织需允许预览功能。用量按参与模型的标准 token 计价。

企业向新增 autoTier 托管默认（efficiency／balance／intelligence），以及可选的 OpenTelemetry 身份采集（默认关）。Visual Studio Magazine 对上述要点做了二次梳理，与官网一致。本卡不写 Cursor——Cursor 栏本窗仍无新 changelog。

升级建议：日常编码可直接升 1.140；要用多文件夹或远程委派，先读实验开关与信任文件夹要求。HydraFusion 适合「一条提示里的大块编码任务」，短问答未必更划算。
