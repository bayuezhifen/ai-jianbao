身份与访问

微软：把 AI 代理当「内部人」管——独立身份、动态权限与条件访问

Microsoft Security 10/19 博客扩展 Project Perception：本地代理发现扩至约 60 种，Entra Agent ID、任务级动态权限与 Dynamic Conditional Access 把「模型供给智能、控制面保留权威」落到产品叙事。

2026-10-20 身份与访问

微软身份与网络访问 CVP Nadim Abdo 于 10 月 19 日在 Security Blog 发文《Agents are your newest insiders》。立论很直接：代理会写代码、批报销、调工具，能力来自对公司数据与系统的访问；访问一开，风险画像就接近「内部人」——未必恶意，但可被提示注入、配置漂移或凭证滥用带偏，且以机器速度连续动作。

Satya Nadella 被引述的原则是：把「智能供给」与「权威控制」拆开，不要让模型当自己的安保官；能访问什么、能做什么、该不该继续跑，必须放在模型够不着的控制面。文中据此展开 Know / Contain / Protect / Adapt 四条连续责任，并宣布把 Project Perception 从「用代理做防御」扩到「防代理成为失控内部人」。

产品增量包括：本地代理发现再加约 35 类，合计支持约 60 种本地代理（点名含 Claude Code、OpenAI Codex、GitHub Copilot 等），纳入统一注册表；扩展 Microsoft Entra Agent ID，让代理拥有与赞助员工分离的一等身份；引入 Dynamic Permissions（默认无权限或最小权限，按任务授权、限时收回，高影响动作可要求可证明的人类批准）；以及 Dynamic Agent Risk + Dynamic Conditional Access——风险升高时可按梯度收权限、保读禁写、缩网络、要求人工批准，直至隔离运行时或停跑，而不是只会「一刀关掉」。

Guardian Agents 与 Playbooks 被描述为「人定目标与审批边界、代理执行连续安全操作」。文末指向 Ignite 进一步讲解。这是官方安全叙事与能力路线图，不是客户环境已默认全开的变更说明；具体许可与滚动节奏需对照 Entra / Agent 365 文档。

本窗边界：ConnectWise Cloud Backup OAuth 供应链晨报（10/19）已收，不回炒。本条只覆盖微软「代理身份与动态控制」这一官方增量。
