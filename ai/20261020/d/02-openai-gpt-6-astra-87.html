OpenAI：低资源语言编码大跃升，GPT-6 Astra 在 20 语种平均通过率约 87%

官方发布 MultiLangBench 与 COBOL 迁移评测：面向 COBOL、Fortran、Visual Basic 等「训练语料少」的语言，新一代模型在从零实现与行为保持迁移上均显著高于上一代。

2026-10-20 OpenAI

OpenAI 于 10 月 19 日（约世界时正午，上海晚间）在官网发布《Advancing Coding in Low-Resource Programming Languages》。核心不是新聊天功能，而是承认：COBOL、Fortran、OCaml、Visual Basic 等语言在开源与文档上远少于 Python/JavaScript，却撑着银行、柜员机、天气预报与核安全分析等关键系统；客户反馈里，编码模型在这些语言上经常「够不着」。

公司为此公开两套评测。MultiLangBench 要求模型在指定语言里从零搭出一套与 SQLite 兼容的数据库引擎，用同一套库文件接口跨语言对照；官方称 GPT-6 Astra 在 20 种语言上平均测试通过率约 87.4%，对比 GPT-5.6 Sol 约 26.8%，且每种语言都有提升——例如 COBOL 约 10.9%→72.1%，Fortran 约 21.4%→83.5%。成本更低的 GPT-6 Luna 平均约 40.3%，估算 API 成本大约低 78%。评测设置与测试套件已放到 GitHub。

第二条是 COBOL 迁移：把程序迁到 C++/Java/Kotlin/Python/Rust，要求在隐藏测试上做到可观察输出的字节级一致，以保住定点运算、缺省记录处理等「写在代码里的业务规则」。官方称 GPT-6.1 Sol 在低推理力度下准确率约 86.6%（上一代同设置约 5.4%），高推理力度下约 97.9%。文中明确：评测进步不等于生产可直接上线，仍须专家复核与业务规则测试。

本窗边界：昨午已收的 Dots 欧盟可用性、八州诉讼等不回炒；GPT-Live 语音等更早窗口亦不展开。本条只覆盖「低资源语言编码评测 + 官方数字」这一增量。二手稿若把 Astra/Luna 写成「全面取代旗舰聊天模型」，与原文「编码能力进展」不符，本简报不采纳。

对运维与现代化团队：若仓库里仍有 COBOL/Fortran 债，可以把 MultiLangBench 与迁移评测当作「模型能不能碰」的参照，而不是「一键重写合规」的许可证。

交叉核对

  • 多方一致：官方 10/19 博客发布；MultiLangBench 与 COBOL 迁移两套评测；Astra/Luna/6.1 Sol 数字与官网一致；评测已开源。
  • 分歧：部分转述突出「87% 全能」，原文是 20 语种平均通过率，COBOL 仍是最难一档。
  • 待确认：API 上各模型对上述语言的默认路由、企业 SLA、与真实遗留仓库差距。
