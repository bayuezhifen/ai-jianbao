GitHub 异步合并 API 正式可用：支撑堆叠 PR 与合并队列自动化

GitHub Changelog 10 月 1 日宣布 async merge API 一般可用：用 PUT 提交、GET 轮询状态，可合并单个或堆叠 PR、入合并队列或直接合并，并成为官方推荐的程序化合并路径。

2026-10-02 开发者工具

同步 REST 合并与 GraphQL mutation 在繁忙仓库里容易把自动化卡在「一次请求等复杂合并跑完」。异步合并 API 把提交与完成拆开：客户端 PUT 发起合并，拿回 request ID 后再 GET 查进度；在权限允许时可选择绕过部分规则。GitHub 写明这是目前唯一支持堆叠（stacked）pull request 的合并 API，并建议新自动化优先改走此路径。

同日 Changelog 还有 Actions Runner Controller 0.15.0、私有漏洞报告速率限制与结构化表单等条目；晨报开发者工具栏已写 Copilot「计算机使用」公测与 JetBrains Air IDE 插件 EAP，故本卡只单列异步合并 GA，不把同日其他 changelog 全部铺开。

适用读者是做合并队列、发布机器人或堆叠 PR 工作流的平台工程／DevOps：迁移时需改客户端为轮询模型，并复核 bypass 权限与审计日志。文档链在 Changelog 正文中给出。

与晨报区分：不复述 Copilot computer use；异步合并是晨报未入库的平台 API 增量。
