操作系统与桌面（Windows、macOS、Linux 发行）

微软 Execution Containers 正式上线：在 Windows 11 上用系统级容器框住 AI 智能体

微软 10 月 7 日宣布 Microsoft Execution Containers（MXC）正式上线：开发者和 IT 用一份策略声明智能体能碰哪些文件、连哪些网络，由操作系统负责强制执行，智能体自己改不了。

2026-10-08 操作系统与桌面（Windows、macOS、Linux 发行）

微软 Windows 平台与开发者副总裁洛根·艾耶在博客中说，企业面对智能体时常常只有两个坏选择：要么放开权限碰运气，要么干脆禁用、放弃效率。微软的思路是把智能体安全拆成三层——限制它能做什么的「隔离」，区分它和真人的「身份」，以及让组织能统一管控的「管理」。MXC 是其中最先落地的隔离层。

博客举了一个例子：让编程智能体改网站，它需要读写代码仓库、读取生产服务器配置，但不应该改配置。没有边界时，智能体可能认为「直接改配置最快」而把线上网站弄坏。MXC 的原则是「智能体不能当自己的安全裁判」：开发者用统一的 JSON 配置声明所需资源，策略放在智能体控制范围之外，模型、生成的代码或插件都无法给自己加权限。

隔离强度分四档：进程容器最轻量，Windows 用 AppContainer、macOS 用 Seatbelt、Linux 用 Bubblewrap；会话容器仅限 Windows，让智能体在独立账户和独立桌面里运行，剪贴板和输入都与用户分开；WSL 容器面向 Linux 工具链；微虚拟机提供硬件级隔离，目前为实验功能。策略可以管控文件系统、网络进出和桌面界面访问。为了帮人写出「最小权限」策略，Windows 上还提供「学习」和「宽松」模式：前者拦截并记录越权操作，后者只记录不拦截，便于先观察智能体到底要用哪些资源。

生态方面，GitHub Copilot、OpenClaw、OpenAI Codex、Replit、LM Studio 和 Unsloth 已支持 MXC；Anthropic Claude Code、Perplexity、Manus、Raycast 等表示将跟进。英伟达把 OpenShell 接入 MXC，补充推理服务访问、凭据管理和审计。Windows 365 云电脑对 MXC 的支持同步正式上线。

尚未到位的部分包括：Intune 管理 MXC 进程容器的策略、用 Microsoft Entra 区分智能体与真人的活动，以及把 Agent 365 管控延伸到本地智能体，微软都只说「即将推出」。这次发布与当天的 RTX Spark 电脑、Surface 新品是同一套叙事：微软想让 Windows 成为运行智能体最安全的桌面系统。
