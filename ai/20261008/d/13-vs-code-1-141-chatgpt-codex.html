VS Code 1.141：智能体沙箱覆盖三大平台，可接着用 ChatGPT 里开的 Codex 对话

VS Code 1.141 于 10 月 7 日发布，主题是管住智能体：Copilot 的终端沙箱扩展到 Windows、macOS 和 Linux，企业可强制开启；同时可以在 VS Code 里接着用 ChatGPT 应用或 Codex CLI 里开的对话。

2026-10-08 开发者工具（IDE、CI、包管理，Cursor 以外）

沙箱是这一版最重要的变化。开启 chat.agent.sandbox.enabled 后，Copilot 智能体在执行受支持的操作时，对文件和网络的访问会受到限制，用来降低模型失误、提示词注入、不可信依赖和本地工具服务器带来的风险。根据平台和操作类型，限制由操作系统机制或智能体宿主进程内部检查实现，Windows 需要先装好相应系统更新。开启后，本地启动的 MCP 服务器和语言服务器默认也进沙箱。微软说明，沙箱只是多一层防护，不能替代终端安全软件。

企业管控方面，管理员可以用统一托管设置要求开启沙箱并禁止绕过（预览）；旧的 VS Code 沙箱设置和设备策略被标记为弃用。管理员还可以选择在遥测中记录操作系统用户名和主机名，方便把智能体会话对应到具体的人和机器，这一项默认关闭。

会话管理上，新的「工作树清理」可以查看闲置智能体会话占用了多少磁盘，按需或自动删除，正在运行或置顶的会话受保护；智能体窗口支持把多个会话拼成网格并排对比；后台运行的命令会在输入框上方以「后台终端」标签列出，可随时查看输出。

跨应用衔接是另一亮点：在 ChatGPT 应用或 Codex CLI 里开始的 Codex 对话，可以在同一台电脑的 VS Code 智能体窗口里接着聊，历史完整保留，之后还能切回去；ChatGPT 额度用完时，也可以换成 Copilot 模型继续。同一时间只能有一个应用发送消息。

其他更新包括：可同时登录多个 GHE.com 和 GitHub Enterprise Server 实例（新设置 github-enterprise.uris）；单个光标粘贴多行文本块时可逐行分布到后续各行；GitHub Pull Requests 扩展实验性支持堆叠式 PR。整体来看，VS Code 与 Windows 当天推出的 MXC 方向一致，都在给智能体划定可审计的边界。
