GitHub Copilot 本地沙箱正式可用，智能体工具调用受文件与网络策略限制

GitHub 10 月 7 日宣布 Copilot 本地沙箱在 Copilot CLI、Copilot 应用以及使用 Agent Host 的 VS Code 会话中正式可用。工具执行由微软 Execution Containers 落到操作系统控件，可限制文件系统、网络与凭据访问，无额外收费。

2026-10-08 开发者工具

GitHub Changelog 写道，本地沙箱现已在 GitHub Copilot CLI、Copilot 应用，以及使用 Agent Host 的 VS Code 会话中一般可用。开发者或组织用策略规定智能体发起的命令能读改哪些目录、能否访问互联网与本地网络、以及能否碰到 Git / GitHub CLI 凭据；本地 MCP 与语言服务器在支持范围内也可纳入同一边界。

底层依赖微软 Execution Containers（MXC）：把一份通用沙箱策略翻译成 Windows、macOS、Linux 上的原生操作系统控制。官方特别区分「模型在哪里跑」和「工具在哪里执行」——无论 Copilot 选用哪家模型，工具侧都走同一套沙箱策略。企业可强制开启并禁止开发者削弱策略。功能包含在 Copilot 订阅内，不另收费。

文档站点同步提供了「关于云端与本地沙箱」「使用本地沙箱」「配置本地沙箱设置」等页面，CLI 可用 /sandbox 配置。这与晨报 VS Code 1.141 里的「智能体沙箱」是同一波安全方向上的产品化：晨报写的是编辑器侧能力上线，本卡写的是 Copilot 品牌下本地沙箱宣告 GA，并点名 MXC 作为跨平台落地层。

对日常开发的影响是：想让智能体更自主地改代码、跑命令，组织终于有一条不额外买产品、又能在本机收紧边界的默认路径；代价是要认真写策略，并接受部分本地工具在沙箱外不可用或需显式放行。
