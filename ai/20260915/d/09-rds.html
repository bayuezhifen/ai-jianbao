操作系统与桌面

微软紧急带外补丁修复九月安全更新导致的 RDS 故障

九月 Patch Tuesday 安全更新引发远程桌面服务不稳定后，微软于 9 月 14 日发布多款带外累积更新（含 KB5129195 等），修复 RDS，并顺带处理部分 Hyper-V 与 USB 音频回归。

2026-09-15 操作系统与桌面

微软在 2026 年 9 月 8 日推送的安全更新上线后，多地管理员反馈 Remote Desktop Services（RDS）出现连接掉线、登录失败，乃至卡在「Please wait for the Remote Desktop Configuration」界面。连带的 MMC、RDS Licensing Diagnoser、资源管理器以及 Windows Update 页面也可能无响应。微软随后在支持文档中确认该已知问题，并曾给出组策略缓解与卸载安全更新等临时手段——后者虽能恢复远程桌面，但会一并失去当月安全修复。

9 月 14 日，公司以带外（out-of-band）方式发布多条累积更新。面向 Windows 11 24H2/25H2 的是 KB5129195（分别升至约 26100.9457 / 26200.9457）；26H1 对应 KB5129194；Windows 10 21H2/22H2（含 ESU 场景）为 KB5129236；Windows Server 2019/2022/2025 则分别有 KB5129238、KB5129237、KB5129235。BleepingComputer 与 Pureinfotech、Windows Latest 等报道列出的包号基本一致；服务器侧说明指出，回归与 Server 2025 的 KB5122871、Server 2022 的 KB5122882 等相关九月包有关。

客户端路径上，KB5129195 等可通过 Windows Update、Windows Update for Business、Microsoft Update Catalog 与 WSUS 获取，部分渠道称会按策略自动下载。服务器相关 OOB 包则更依赖 Update Catalog。Windows Latest 还指出，KB5129195 为强制累积包，除 RDS 外还补强了对 CVE-2026-62721（用户态电源服务提权）的修复，因其初版安全更新未完全关闭该漏洞。

同一批 OOB 也修复了 Hyper-V 上由 Host Compute Service 管理的 Linux 虚拟机通过 Plan9 共享主机文件夹时「看不见或无法访问」的问题，并部分修复 USB Audio Class 1.0 在 8 声道、3D 等对多声道模式下的异常。微软与多家媒体均强调：设备完全无法启动、Device Manager Code 10、无声等更严重的 USB 音频症状仍未在本轮解决，厂商仍在跟进。

对运维而言，优先安装对应分支的 OOB 累积包，可避免为恢复远程桌面而回退九月安全修复。Windows Latest 另跟踪到 Explorer 崩溃、File History、AMD GPU 等社区报告，微软尚未在本轮 OOB 发行说明中全部确认或修复；若环境仍异常，应保留诊断数据并对照官方已知问题列表，而不是自行假设已被 KB5129195 覆盖。

交叉核对

  • 一致：BleepingComputer、Pureinfotech、Windows Latest 均确认 9/14 OOB 修复九月更新引入的 RDS 不稳，并列出 KB5129195（Win11 24H2/25H2）等包号。
  • 一致：微软支持页（KB5124008 已知问题）描述的 RDS 症状与媒体报道吻合；OOB 另含 Hyper-V Plan9 与部分 USB 多声道音频修复。
  • 单源/待核：Windows Latest 关于 CVE-2026-62721「初版未完全修复」及 Claude Cowork/Plan9 关联叙述，主要来自该站与微软沟通，宜对照 MSRC/发行说明原文。
  • 未解决：多家来源指出 USB Audio Class 1.0「无法启动/无声」等仍未完全修复；Explorer/File History/AMD GPU 等社区问题未进入本轮官方修复列表。
