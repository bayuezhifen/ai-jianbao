Trigger.dev v4.6.0：chat.agent 托管 streamText、自有 TranscriptStorage、chat.close()

Trigger.dev 于 9 月 14 日发布 v4.6.0，围绕 chat.agent 强化托管 streamText、可自建 TranscriptStorage、动作为完整回合驱动，以及 chat.close()；并默认切到 Zod 4，收紧会话 .in 通道读取权限。

2026-09-15 开发者工具

后台任务平台 Trigger.dev 发布 v4.6.0。官方 changelog 将该版本重心放在 chat.agent：开发者在 run 回调中直接拿到已注入代理配置的托管 streamText，无需再手动展开 chat.toStreamTextOptions()。此前若漏掉展开或在其后覆盖 tools/prepareStep，会静默关掉转向（steering）、压缩与注入上下文；托管入口会合并技能工具并组合 prepareStep，system 提示也只能在调用点、agent 配置或 chat.prompt.set() 三处之一设置，重复设置会抛错而非悄悄丢弃。

会话持久化方面，新增 TranscriptStorage 适配器（load/save），运行时在每次成功/失败回合及改写历史的动作后驱动保存。默认仍用平台快照；若指定自有 storage，对话会写入开发者自己的数据库。每次保存同时携带自上次以来的增量（便于行存 truncateAfter 撤销）与完整誊本（便于文档库整写）。配套提供 chat.createLoadTranscriptAction、useLoadTranscript，以及 @trigger.dev/sdk/ai/test 中的 runTranscriptStorageTests 契约测试。

Undo / edit / regenerate 等动作现可返回 chat.turn()，在改写后的历史上真正跑一轮（含系统提示、工具、steering、压缩、生命周期钩子与持久化）。旧版从 onAction 直接返回 StreamTextResult/字符串/UIMessage 的写法已废弃并会抛错。另新增 chat.close({ reason })，可从代理内部关闭会话：会话行标记关闭、后续发送返回 HTTP 409，且不再调度续跑，适用于预算上限或目标完成等场景。

破坏性变更包括：内部默认使用 Zod 4，最低支持 Zod 3.25.56；读取会话 .in 通道（GET /realtime/v1/sessions/{id}/in 等）现需密钥，仅持有公开令牌（即便含 read:sessions）会收到 403，但仍可读 .out 并追加 .in。发行说明还列出 Playwright 1.58+ 构建扩展修复、部署日志断线体验、敏感信息收敛，以及队列指标、LLM 成本双计、重试去重等一批云端/自托管服务端改动。

升级路径为将 trigger.dev/* 升到 v4.6.0（npx/pnpm/yarn/bunx 的 trigger.dev@latest update）；自托管用户需将镜像更新到 ghcr.io/triggerdotdev/trigger.dev:v4.6.0。若类型检查或部署因 Zod 失败，官方指向 Zod 兼容性指南。公开材料以官方 changelog 为主，第三方深度评测尚少，集成前宜对照文档核对 breaking changes。

交叉核对

  • 一致：功能要点（托管 streamText、TranscriptStorage、chat.turn()/chat.close()、Zod 4、.in 需密钥）均出自 Trigger.dev 官方 v4.6.0 changelog。
  • 背景：v4.5.0 changelog 表明 chat.agent 此前已 GA；本版是在既有会话/实时传输之上的持久化与动作模型加固。
  • 单源：详细 API 行为与破坏性变更目前主要依赖官方发行说明；GitHub SDK CHANGELOG 页面抓取未返回可用正文，未另作独立交叉。
  • 待观察：社区迁移踩坑与生产侧 TranscriptStorage 适配器实践报道尚少。
