Node.js 发布 26.13.1、24.22.3 和 22.23.5 安全更新，修复 16 个漏洞，最高为高危

Node.js 项目 11 日为仍在维护的三条版本线发布安全更新，一共修补 16 个漏洞，其中 7 个被标为高危。官方建议尽快升到对应补丁版本并重启服务。

2026-11-11 语言 / 运行时 / 框架

Node.js 项目在 11 日的安全公告里宣布，为 26.x、24.x 和 22.x 三条仍在维护的版本线提供更新，对应版本号分别是 26.13.1、24.22.3 和 22.23.5。公告写明，这次修复里最高的严重级别是「高」。把公告中逐条列出的编号数一遍，一共是 16 个漏洞：7 个高危、6 个中危、3 个低危。其中部分还涉及 llhttp、undici 和 sqlite 等随发行版一起走的依赖更新。已经停止维护的旧版本同样会受这些漏洞影响，但不会再得到补丁，公告再次提醒应迁到仍受支持的版本。

高危条目主要集中在 HTTP/2 和 TLS 上，而且多数可以被未认证的客户端触发。例如 CVE-2026-123863：攻击者可以让 HTTP/2 会话在拆除时触发断言失败，从而使进程退出，明文和加密连接都适用，公告把它写成此前 CVE-2024-27983 修复没有盖住的变种。CVE-2026-123864 更麻烦一些：在 HTTPS 场景下，一次零长度的 TLS 写入可能重入解析器，让服务器把堆上本属于其他连接的内存，包括私钥或其他用户的请求，复制进当前请求体；明文的 node:http 不受这条影响。CVE-2026-123865 则是会话在关闭过程中遇到协议错误时清理不彻底，造成内存和文件描述符一直泄漏，攻击者还可以先发送 GOAWAY 来稳定地触发。此外还有把已释放的响应内存发给对端、TLS 服务器上可远程触发的未捕获异常、TLS 1.2 重协商时客户端单方面改掉服务器名以绕过客户端证书校验，以及 respondWithFile 在重置时的释放后使用。

中危和低危也不宜完全略过。中危里包括超长 origin 导致的堆溢出、按主机名配置的双向认证证书机构校验失效、HTTP/2 会话内存上限统计不准、代理密码出现在错误信息里、以及 https.Agent 跨策略复用 TLS 会话造成的证书校验绕过。低危则涉及权限模型里通配符路径授权过宽、fs.watch 递归监视时泄漏本应拒绝的子路径名称，以及 zlib 参数更新与销毁顺序不当引发的内部断言。对普通服务来说，最应当先处理的仍是那几条可远程触发的高危 HTTP/2 和 TLS 问题。

一个值得单独说明、但不必写成产品新闻的细节是：公告在若干高危条目的致谢里写到，克里斯·罗尔夫与 Claude 以及 Anthropic Research 合作报告了这些漏洞，修复由 Node.js 维护者完成。这只说明漏洞是怎么被发现的，并不等于 Anthropic 发布了新产品，因此不单独进入 Claude 栏。

对使用者而言，动作很直接：按自己所在的版本线升到 26.13.1、24.22.3 或 22.23.5，然后重启进程或服务，让新的二进制真正跑起来。只把包下载下来、却让旧进程继续服务，等于没有修。若生产环境还停在已经结束维护的版本上，这次不会有官方补丁，只能先升级到仍受支持的线路。公告没有把这些漏洞写成「已在野外大规模利用」，但也没有排除已经被探测的可能。对于对外提供 HTTP/2 或 HTTPS 的服务，把补丁尽快打上，是眼下最稳妥的做法。

交叉核对

  • 官方为首要依据：nodejs.org 11 日安全公告列出三条版本线的补丁编号，并逐条给出 CVE 与严重级别。将公告条目计数后为 16 个漏洞（7 高、6 中、3 低），与安全媒体对同一公告的概括一致。
  • 影响范围：多条高危问题可被未认证客户端触发，主要影响 HTTP/2 与 HTTPS；明文 HTTP 不受其中一条堆内存泄露影响。三条仍在维护的版本线最高级别均为高危。
  • 待确认：这些漏洞是否已出现大规模野外利用，公告未作断定；旧的已停止维护版本受影响但不会再得到官方补丁。
