OpenAI 与思科推出开源运行时 Shirudo，可在补丁到位前为正在运行的 Linux 系统加上防护

OpenAI 与思科 11 月 23 日宣布开源项目 Shirudo。它基于 eBPF，旨在让运维人员不必等待正式补丁、也不必重启，就能为正在运行的 Linux 系统加上临时防护。两家公司称，在受控测试中，为 Elasticsearch 生成的防护挡住了一次 Java4Shell 利用尝试。

2026-11-24 OpenAI

OpenAI 官网与思科新闻室都把发布日期写在 2026 年 11 月 23 日。项目名称 Shirudo 来自日语里的「盾」。双方的定位很明确：这不是用来替代正式补丁的新操作系统，而是给安全团队争取时间——在补丁还要几天甚至几周才能测完、装上的时候，先给正在跑的 Linux 服务加上一层可撤销的防护，并且尽量不中断业务。

技术路径建立在 eBPF 上，也就是在不改内核源码的前提下，往内核里加载一小段经过约束的程序。OpenAI 的介绍说，测试中由 Codex 生成的防护，在不必重启的情况下，挡住了对正在运行的 Elasticsearch 服务发起的 Java4Shell 利用。思科新闻稿还提到，针对不久前的 PHP 高危漏洞，同样写出了能够检测并拦截利用尝试的代码。这些都是两家公司公布的受控测试结果，不能直接外推成「所有生产环境都已经安全」。

为了让智能体写出的防护可以被人接受，双方把信任链条写进了方案本身。思科新闻稿称，防护只有在证据表明它是安全的之后才会启用；每一份防护都要经过密码学签名，主机在运行前可以校验来源，即便攻击者已经拿到管理员权限。OpenAI 还强调，许多团队用的是同一类软件，因此把工具放在公开仓库里，让一家的做法可以被别的团队复用，而不必从头再做一遍。项目目前放在 GitHub 的 shirudo-dev/shirudo 仓库，并邀请开发者、安全研究人员和基础设施运维人员一起补测试、跑内核版本、指出误伤正常流量的地方。

思科总裁兼首席产品官杰图·帕特尔把这套思路概括成「自我防护的基础设施」：安全团队需要能跟上由人工智能驱动的攻击速度，在正式补丁安全上线之前先把系统护住。OpenAI 总裁兼联合创始人格雷格·布罗克曼则说，他们已经在给防御方更好的模型和工具去发现、修复漏洞，但今天找到一个缺陷，并不等于明天就能给每一台机器打上补丁；与思科合作，是为了让必须持续运行的系统在修复落地之前先有一层保护。

对运维人员来说，这个项目眼下更像一份可以试验的开源运行时，而不是已经通过大规模生产验证的标准控件。它要面对的实际问题也很具体：防护会不会挡住正常请求、签名与策略由谁审批、以及它能否覆盖内核和发行版的差异。两家公司都没有把它写成可以永久代替补丁的方案。更稳妥的读法是：在漏洞披露到补丁铺开之间，多了一条可以公开审看的临时防护路径，效果如何，还得看社区后续的复现和真实部署。

交叉核对

  • 一致处：OpenAI 官网与思科新闻室均于 11 月 23 日宣布 Shirudo，定位为基于 eBPF 的开源运行时，可在不必重启的情况下为运行中的 Linux 系统提供临时防护；仓库地址均为 github.com/shirudo-dev/shirudo。
  • 测试口径：OpenAI 写到受控测试中防护挡住了对 Elasticsearch 的 Java4Shell 利用且无需重启；思科新闻稿还提到对 PHP 漏洞的检测与拦截。两者都是官方受控测试，并非第三方复现。
  • 署名与启用条件：思科新闻稿写明防护需经密码学签名，并在证据表明安全后才会启用。
  • 待确认：生产环境中的误报率、对多种内核与发行版的兼容性，以及社区后续贡献规模，目前还没有独立评估。
