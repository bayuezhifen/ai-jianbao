OpenAI 与 ServiceNow 扩大合作：ChatGPT 内接工作流，Codex/安全/语音分阶段落地

OpenAI 于 10 月 28 日宣布扩大与 ServiceNow 的合作：把模型与代理嵌入 ServiceNow 产品，同时把 ServiceNow 业务上下文与动作接到 ChatGPT 与 Codex。MCP 插件已可在 OpenAI 市场取用。

2026-10-29 OpenAI

OpenAI 官方稿写明：双方在今年 1 月合作基础上加码。一侧是 ServiceNow 产品更多用上 OpenAI 模型与代理；另一侧是客户可把自有 ServiceNow 实例连进 ChatGPT，在对话里查相似事件、评估变更风险、更新工单，权限仍走 ServiceNow Action Fabric 既有规则。

路线图分三块：应用开发——计划把 Codex 接进 AI Workflow Factory，并给 Build Agent、Autonomous Engineer 供模型；网络安全——结合 OpenAI 安全能力与 ServiceNow 资产/身份/业务上下文，协助排漏洞与协同修复；语音——在 Super Intelligence Control Tower 里用语音描述用例、补全评估字段。ServiceNow 还预览在 ChatGPT 内做交互式值班体验。

人员侧，ServiceNow 打算把 ChatGPT Work 与 Codex 扩到全员，而不只是工程团队；OpenAI 自身也在用 ServiceNow 工作流。可用性：ServiceNow MCP 插件「今天」可在 OpenAI 市场使用，增强能力预计 2026 年底前后；语音能力约 2027 年一季度；安全能力 2027 年 1 月早鸟、二季度 GA；Codex 进 Workflow Factory 约 2027 年。

边界：这是产品集成与路线图，不是新一代基础模型发布。昨晨已收 Oracle 应用进 ChatGPT、昨午已收拟购谷歌 TPU，同属 OpenAI 生态铺开，本条只收 ServiceNow 这一侧。不要把「计划中」的安全/语音写成已全面上线。

交叉核对

  • 多方一致：OpenAI 官方 10-28 稿；MCP 插件已上架；安全/语音/Codex 多为 2027 节奏。
  • 分歧：媒体对「企业工作流」与「全员 Codex」强调不一，实质同稿。
  • 待确认：增强 MCP 能力的具体功能清单与区域限制；联合安全方案的客户早鸟名单。
