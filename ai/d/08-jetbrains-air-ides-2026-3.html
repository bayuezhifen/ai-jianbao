JetBrains 随 2026.3 在 IDE 里正式推出 Air，用来同时跑和审阅多种编程智能体

JetBrains 11 日随 2026.3 正式在 IDE 里提供 Air，用来跟踪、并排运行和审阅 Junie、Codex、Claude Agent、GitHub Copilot 等编程智能体。官方说不必另买 JetBrains AI 订阅，也可以接上自己已有的模型服务。

2026-11-11 开发者工具

JetBrains 在 11 日发布了面向旗下 IDE 的 2026.3，并把 Air 作为正式能力放进编辑器。官方博客的发布时间为当天上午 10:38（中欧时间），对应上海时间 17:38，落在本窗口内。公司给 Air 的定位很具体：智能体写的代码变多以后，瓶颈会转到审查；开发者需要一个地方看清改了什么、决定这些改动该不该进仓库，并在会话结束后还能维护这些代码。Air 就是这个放在 IDE 里面的工作台，而不是又一个独立的聊天窗口。

功能上，它允许并行开多个智能体会话，在一个视图里跟踪哪些还在跑、哪些在等你、哪些有未读结果，并在需要人介入时发出通知。每个会话可以使用自己的本地 Git 工作树，避免并行修改互相覆盖；官方也老实说，智能体自己建出来的工作树目前还不会被 Air 跟踪，这一块仍在开发。常用的「哪个智能体、哪个模型、哪套说明」可以存成预设，下次直接调用。支持的智能体包括 Junie、Codex、Claude Agent 和 GitHub Copilot，其他兼容的智能体则可通过 ACP 接入。已经装在本机的可以导入，也可以从注册表添加。

审查是这次着墨最多的部分。会话结束后，开发者可以打开审查面板，查看这一轮改动，再用 IDE 自己的能力去做检查：跳转代码、跑代码检查和测试，在 IntelliJ IDEA 和 CLion 里还可以驱动调试器。针对某一行留下的「代码备注」会连同上下文送回当前会话，用来要求修改或提问；终端里跑的智能体也可以用同一套备注来做下一轮。Air 还把 IDE 的 MCP 服务和内置技能交给受支持的智能体，例如检查、构建和运行配置、查询数据库、调用重构。代码补全仍然可用，且不占用 JetBrains AI 额度；「下一步编辑建议」则需要登录 JetBrains AI 或 GitHub。

收费和去留也写得比较明白。官方强调，不一定要购买付费的 JetBrains AI 订阅：可以用已有的服务商订阅、接口密钥，或 JetBrains AI。Claude 的 Pro 或 Max 订阅也可以在 Air 的终端界面里配合 Claude Code 使用，该界面会作为全屏的 IDE 标签打开。如果不想用，可以在设置的插件列表里关掉 Air，再重启 IDE。公司把「开发者仍然坐在驾驶席上」写成产品原则：可以只问一句、可以交出去改、也可以继续自己写。

对日常使用 JetBrains 工具的人来说，这是 2026.3 里最值得注意的一条，因为它不再只是把某个自家模型塞进编辑器，而是把已经在用的多种智能体收拢到同一套审查和调试流程里。是否好用，还要看工作树跟踪是否补齐、不同智能体的能力差异，以及审查面板能不能真正减少返工。这些只能等更大范围的使用反馈，不能从一篇产品介绍里提前下结论。IntelliJ IDEA、PyCharm、CLion 等产品各自的 2026.3 说明里，也对 Air 作了相互印证。

交叉核对

  • 官方一致：JetBrains Air 博客、产品页以及 IntelliJ IDEA、PyCharm、CLion 的 2026.3 更新说明，都把 Air 写成随 2026.3 正式进入 IDE 的智能体工作台，并列出并行会话、工作树、预设和审查能力。
  • 时间：WordPress 记录的发布时间为 2026-11-11 09:38:53 UTC（中欧时间 10:38），上海时间为 17:38，属于本窗口。
  • 待确认：智能体自行创建的工作树跟踪仍未完成；不同智能体在调试、检查上的实际能力，以及长期使用中的审查效率，都还有待用户反馈。
