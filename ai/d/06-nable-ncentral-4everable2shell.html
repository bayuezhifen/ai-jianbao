漏洞与勒索

N-able 调查针对已打补丁 N-central 的新利用链，称问题取决于对公网开放的非默认 Legacy API

N-able 在 11 月 12 日表示，正在评估针对本地版 N-central 2026.4.1 热修复 2 的新公开披露。公司初步判断，所描述的服务器问题取决于一项默认关闭、且被暴露到公网的 Legacy API。托管环境据称不受影响，公司呼吁客户立刻关闭该接口。

2026-11-13 漏洞与勒索

The Hacker News 11 月 12 日报道，独立研究员肖恩·贝尔斯在此前披露的 Able2Shell 之外，又公布了名为 4EverAble2Shell 和 Agent2Shell 的新问题，并给出可在 N-central 2026.4 热修复 2（构建号 2026.4.1.26）上使用的概念验证。这个热修复正是 N-able 在 11 月 10 日为修补 Able2Shell 而发出的版本。按研究员的说法，4EverAble2Shell 可在未认证情况下以 root 权限在 N-central 服务器上远程执行代码；Agent2Shell 则在已知目标设备编号的前提下，利用十余个漏洞，在受管 Windows 代理上以 SYSTEM 权限执行命令。

N-able 随后给出的初步说明与“补丁完全失效”不是同一句话。公司称，正在调查这份针对本地版、且运行 2026.4.1 热修复 2 的新披露；根据初步核对，所描述的服务器问题依赖于一项非默认配置：Legacy API 被打开，并且暴露在公网。该接口在产品里默认是关闭的，也不被建议开启。公司呼吁客户若尚未关闭，立即关掉 Legacy API，并写明托管环境不受这一项影响。受影响的是美洲、亚太和欧洲的本地部署。

利用情况目前有不同口径，必须分开写。The Hacker News 引述 Previdian 创始人瑞安·杜赫斯特说，概念验证公开后数小时内，就观察到针对 4EverAble2Shell 的探测，来源地址为 157.20.241.16；截稿时还没有成功入侵的证据。他们看到的攻击链是：先尝试利用 11 月 6 日已修补的 Apache Axis 漏洞 CVE-2026-90436 取得代码执行，再试图用 4EverAble2Shell 提升到 root，然后用 curl 从同一地址下载脚本。watchTowr 也在社交网络上说，看到针对开启了 Legacy API 的 N-central 的探测。另一方面，另有安全公司写到生产服务器被植入门罗币挖矿程序并给出受害者数量，这与“尚未看到成功利用”并不一致，本刊无法在未打开其原始取证的情况下采用这些数字，只在此标明存在不同说法。

再往前一天，N-able 在 11 月 11 日的博客里介绍了热修复 2 的背景：所有无需登录即可利用的已知问题已经处理，其余多需要已认证且权限较高的账户，将在后续热修复中继续补。公司当时说，托管实例已由其升级并恢复上线，本地客户应尽快升到热修复 2，并在完成升级前避免把服务器暴露到公网；同时要求所有客户升级 Agent 和 Probe。那篇博客还写，公司观察到与已公开概念验证相关的扫描，但在托管服务器上尚未看到失陷迹象。对已经打过热修复 2 的本地用户，眼下最明确的官方建议仍是：确认 Legacy API 关闭，不要把它暴露在公网，并继续关注后续热修复。

交叉核对

  • 一致处：The Hacker News 和 N-able 都确认存在针对已安装 2026.4 热修复 2 的新披露；官方强调问题取决于非默认且对公网开放的 Legacy API，并称托管环境不受影响。
  • 利用是否已经得手：The Hacker News 引述的威胁情报公司写的是“已观察到探测，截稿时没有成功利用的证据”；另有文章声称生产环境失陷并植入挖矿程序。两说冲突，本刊不把未独立核实的受害者数字写成事实。
  • 11 月 11 日官方博客主要谈热修复 2 本身，11 月 12 日的新信息是“补丁之后仍有新链，且与 Legacy API 有关”。
  • CVE-2026-90436 被写成攻击链的第一环，补丁日期为 11 月 6 日，这是 The Hacker News 对 Previdian 的转述。
  • 待确认：N-able 后续正式公告和补丁编号、Legacy API 相关问题的 CVE，以及是否出现经多方确认的成功入侵。
