VS Code 发布 1.145.3 安全更新，修复多个远程代码执行和工作区信任漏洞

官方安全通告列出至少 10 个漏洞，受影响范围是低于 1.145.3 的版本，其中多条被标为高危，涉及 MCP 安装与通知、调试器自动附加，以及工作区信任被绕过。这是安全补丁，不是新功能版本；请尽快升级。

2026-11-10 开发者工具

微软在 11 月 10 日为 Visual Studio Code 发布了 1.145.3 安全更新。GitHub 发布记录的时间为当天 18:53:52（协调世界时），换算到上海是 11 月 11 日 2 时 53 分。1.145 稳定版本身是 11 月 4 日发布的，已不在本窗口的新功能新闻范围内；今天这条是随后的安全补丁，发行说明写的是：1.145.3 更新用于解决这些安全问题。受影响范围是低于 1.145.3 的版本，请尽快升级，不要把它当成一次功能迭代。

官方安全通告（GitHub Security Advisory）至少列出 10 个漏洞，评分一律以这些通告为准，不以转述中的更高分数替代。被标为高危且给出 CVSS 的有：CVE-2026-120779（GHSA-66hq-jw93-462h，通过 MCP 征询通知实现远程代码执行，高危，8.3 分）；CVE-2026-119983（通过未校验的 MCP SSE 端点实现远程代码执行，高危，7.7 分）；CVE-2026-114171（通过恶意 MCP 安装链接实现远程代码执行，高危，7.7 分）；CVE-2026-70094（通过 JavaScript 调试器自动附加实现远程代码执行，高危，7.7 分）；CVE-2026-119985（通过网络工作区信任被绕过实现远程代码执行，高危，7.2 分）；CVE-2026-120780（通过 serve-web 发布通道降级实现远程代码执行，高危，7.2 分）。其中第一项的官方评分是 8.3、级别为高危，不能写成与官方通告不符的「严重、9.6 分」。

另外还有三条被标为高危、但此次查询官方接口时没有给出 CVSS 分数的条目：CVE-2026-121662，通过工作区配置里的原型污染绕过工作区信任；CVE-2026-121663，通过设置分组键覆盖绕过工作区信任；CVE-2026-102230，集成浏览器在上传文件时造成信息泄露。再有一条是 CVE-2026-120782，经由智能体发起的本地命令造成命令执行，级别为中等，CVSS 分为 6.8。完整标题和说明见各条 GHSA 与官方更新说明。

从类型上看，这批问题主要集中在三类场景：一是模型上下文协议（MCP）的安装、通知和端点校验；二是调试器自动附加；三是工作区信任被绕过，包括网络工作区、配置原型污染和设置键覆盖。对日常打开未完全信任的仓库、或会安装第三方 MCP 服务器的使用者来说，应把升级放到优先位置，并在升级前避免点击不明的 MCP 安装链接，谨慎对待自动附加调试器和工作区信任提示。具体利用条件和官方评分，仍以 GitHub 通告原文为准。

交叉核对

  • 多方一致：VS Code 官方更新说明与 GitHub 发布记录均确认 1.145.3 于 11 月 10 日发布，用于修复安全问题；受影响范围为低于 1.145.3 的版本。1.145 稳定版的功能更新发布于 11 月 4 日，不属于本窗口的新功能新闻。
  • 评分口径：本条只采用官方 GHSA 给出的级别和分数。CVE-2026-120779 的官方评分是 8.3、高危，不以与之矛盾的「严重、9.6 分」计算。CVE-2026-121662、CVE-2026-121663、CVE-2026-102230 被标为高危，但此次查询官方接口时未返回 CVSS 分数，文中不强行补分。
