漏洞与勒索

微软 agent-framework 的两个 PyPI 版本被植入窃密程序，约一小时后已从仓库下架

Wiz 和 Aikido 披露，微软 Agent Framework 的 PyPI 元包 agent-framework 在 18 日凌晨（上海时间）先后出现 1.26.1 和 1.26.2 两个恶意版本，会在安装后窃取云和持续集成凭证。两个版本约一小时后已从 PyPI 消失；截至截稿未见微软官方定性。

2026-11-18 漏洞与勒索

安全公司 Wiz 和 Aikido 披露，微软 Agent Framework 在 PyPI 上的元包 agent-framework，于 17 日 20 时 35 分（协调世界时，上海时间 18 日 4 时 35 分）之后先后出现 1.26.1 和 1.26.2 两个恶意版本。研究人员称，安装这些版本后，会在 Python 的站点包目录里放下启动钩子，之后每次启动 Python 都会运行一段窃密程序，重点收集 Azure、Azure DevOps 和 GitHub Actions 等环境里的令牌与密钥，并外发到第三方接收服务。两个版本大约在 21 时 30 分（协调世界时，上海时间 5 时 30 分）已从 PyPI 上消失，窗口大约一小时。最近的安全版本是 1.26.0。

Wiz 指出，GitHub 上的 microsoft/agent-framework 仓库里没有对应的 python-1.26.1 标签，1.26.1 只有 wheel 包，并且仍然依赖 agent-framework-core 的 1.26.0，因而“可能”绕过了正常发布流程。Aikido 则强调，两个恶意版本的间隔只有约 33 分钟。两家都没有把根因写成已经查清，也明确说，截至他们发稿时还没有微软官方声明。因此，本报只记录“PyPI 上出现了打着该项目名称的恶意版本，并且很快被拿下”，不写成“微软官方代码仓库已被攻破”或“内部账号确定失窃”。

影响评估需要分开看。Wiz 提到该包每周约有 4.1 万次下载，Aikido 提到每月约 19 万次，量级相近但统计口径不同，不能混用。攻击者使用的接收服务是免费档，有请求条数上限，但这并不意味着风险可以忽略：只要有凭证被发出去，就应当视为可能已经泄露。另外，两个版本留下的钩子文件名并不相同，只搜索其中一个，可能会漏掉另一种。卸载软件包也不能挽回已经送出的密钥。研究人员给出的处理建议很直接：清理钩子文件，并把该环境能够接触到的云和持续集成凭证全部轮换。

这条新闻出在 18 日凌晨的短暂窗口里，前一天的简报不可能写到。它也提醒了一个更普遍的问题：即便是与大厂项目同名的软件包，安装来源仍然是公共仓库里的具体版本号。在官方说明出来之前，开发者和持续集成管理员应当检查自己是否在那一个小时里安装过 1.26.1 或 1.26.2，而不是等待定性后再行动。

交叉核对

  • 一致处：1.26.1 与 1.26.2 两个恶意版本、约一小时后从 PyPI 消失、会留下启动钩子并收集云和持续集成凭证、官方仓库未见对应标签，Wiz 与 Aikido 的核心时间线和现象描述相符。
  • 限制：截稿时未见微软官方声明，根因未确认；不能写成官方仓库失守。两家给出的下载量口径不同，不可混用。本报不扩散完整的外发地址。
