Chrome 158 稳定版上线，一次修复 204 个安全漏洞，其中 6 个为严重级

谷歌 17 日将 Chrome 158 推送到 Windows、macOS 和 Linux 稳定通道，官方列出 204 项安全修复，其中 6 项为严重级。微软当天表示已注意到这批 Chromium 修复，但 Edge 稳定版尚未跟进。

2026-11-18 操作系统与桌面

谷歌 17 日把 Chrome 158 推送到了 Windows、macOS 和 Linux 的稳定通道。官方博客列出的版本号是：Linux 为 158.0.8127.36，Windows 和 macOS 为 158.0.8127.36 或 158.0.8127.37。这篇稳定版说明的重点不在新功能，而在安全修复的数量：一共 204 项，其中 6 项被标为严重级，涉及 WebView、GPU、Media、垃圾回收、ANGLE 和 WebAudio 等组件中的内存破坏问题。官方并未在这篇说明里写这些漏洞已经遭到在野利用，本报也不作这样的推断。

对普通用户来说，这意味着桌面版 Chrome 应当尽快更新到 158 稳定通道。204 这个数字明显高于一次常规小版本常见的修复量，因此即便没有“已被利用”的官方表述，也足够作为本期操作系统栏的主条。需要写明的是，修复清单来自谷歌自己的发布说明，本报没有逐条复核每一个 CVE 的技术细节，只记录官方汇总的数量和严重级分布。

同一天，微软在 Edge 安全更新说明里写了一句很关键的话：公司已经注意到近期的 Chromium 安全修复，正在积极准备推出相应的安全更新。这句话说明两件事。第一，Edge 作为 Chromium 系浏览器，理应跟进这批修复；第二，在 17 日当天，Edge 稳定通道还没有放出对应补丁。按常见节奏，Edge 往往会在之后数日跟进，但截稿时不能让读者以为“所有 Chromium 浏览器都已经修好”。使用 Edge 的用户仍需等待微软的正式安全更新。

本窗口内，Windows 和 macOS 本身没有新的正式系统版本需要单独成条，Linux 也只有常规稳定内核点更，优先度低于这次 Chrome 安全更新。因此，操作系统栏以浏览器补丁为这一窗口的主进展。企业和学校如果统一管控浏览器版本，应当把 Chrome 158 纳入更新计划，并单独跟踪 Edge 补丁是否到达稳定通道。

浏览器自动更新通常会在随后数小时到数天内到达大多数个人设备，但被统一管控的企业电脑可能仍停在旧版本。管理员应当在更新策略里核对这些内部版本号，而不是只看到“158”这个主版本就结束。对仍在使用延长支持或其他分支的环境，也要以谷歌自己的发布说明为准，确认自己是否在这次稳定通道覆盖范围内。

交叉核对

  • 一致处：Chrome 158 于 17 日进入桌面稳定通道、版本号、204 项修复和其中 6 项严重级，均可在谷歌官方发布说明中核对；微软 Edge 安全说明同日承认已注意到 Chromium 修复但尚未提供对应稳定版补丁。
  • 限制：官方未宣称这些漏洞已遭在野利用；本报不扩展成“紧急在野攻击”。
  • 待确认：Edge 稳定通道跟进的具体日期，以及各平台自动更新推送到用户的时间。
