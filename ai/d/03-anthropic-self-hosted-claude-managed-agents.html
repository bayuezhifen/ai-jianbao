Claude / Anthropic

Anthropic 推出自托管版 Claude Managed Agents，会话记录和凭证可放在客户自己的环境

Anthropic 在 11 月 12 日把 Claude Managed Agents 的自托管版本开到私有测试。客户可以在自己的云或机房里运行服务端、数据库和沙箱，会话历史和凭证留在自己这边；但模型推理请求仍要发到外部的模型服务。

2026-11-13 Claude / Anthropic

Anthropic 的产品文档和 Help Net Security 的报道都写到，自托管版 Claude Managed Agents 在 11 月 12 日以私有测试的形式开放，需要通过客户对应的客户经理申请。和过去不同的是：以前客户最多只能把智能体跑代码的沙箱放在自己这边，会话记录、凭证保管和调度仍由 Anthropic 托管；现在客户可以自己运行 Managed Agents 服务端、PostgreSQL 数据库，以及执行命令和文件工具的工作进程。官方文档写得很清楚：Anthropic 对这台自托管服务器没有远程访问权限，也拿不到它的日志。

需要同时写明白的限制是：Claude 模型本身并不在客户网络里运行。每次智能体要询问模型，对话内容仍会发到客户指定的推理服务，默认是 Anthropic 的 Claude API，也可以改成 Amazon Bedrock、Google 上的 Claude、微软 Foundry，或客户自己的网关。也就是说，历史和密钥可以不出自己的环境，但提示词和模型回复还是会离开内网。若客户与 Anthropic 签有零数据保留协议，文档称这些模型调用按普通 Messages API 请求适用同一安排；Anthropic 托管版会由公司保存会话记录，自托管版则由客户自己保存在数据库里。

安全设计按官方的四条原则展开。调度器和沙箱是分开的，会话历史和保险库密钥不进沙箱；对 MCP 工具和受支持的接口调用，凭证由沙箱外的代理附加。客户可以把密钥放进自己的密钥管理服务。环境可以设置允许访问的主机名单，其他地址一律拦住。智能体每一步的工具调用和返回结果可经 OpenTelemetry 导出，方便和现有监控接到一起。Help Net Security 也提醒：这些保护主要覆盖 MCP 和“受支持的接口调用”，智能体若还要访问其他服务，需要事先核对。

自托管也把原来由 Anthropic 承担的运维交给了客户，包括服务器加固、补丁、防火墙和数据库备份。文档还写，部分能力与托管版并不完全对齐，例如要从头建立智能体和数据，不能直接从托管服务里搬过来。这是一项面向已有客户经理通道的私有测试，不是对所有用户默认开放的公共功能。对于把无人值守的智能体用在修构建、做测试或处理告警的团队，意义在于把会话和凭证的控制权收回到自己的安全边界里，而不是把模型本身搬进内网。

交叉核对

  • 多方一致：Anthropic 平台文档和 Help Net Security 都确认 11 月 12 日开放自托管私有测试，客户自行运行服务端、数据库和沙箱，会话记录留在本地，模型调用仍走外部推理服务。
  • 官方文档补充了更细的边界：Anthropic 不能远程访问自托管服务器；发往 Claude API 的请求会带上会话、智能体和环境的内部编号，这些编号不含名称和内容，但编码了创建时间，且无法关闭。
  • 零数据保留：文档区分了托管版和自托管版——托管版由 Anthropic 保存会话，自托管版由客户保存；发给 Claude API 的模型调用仍按其与客户的数据保留协议执行。
