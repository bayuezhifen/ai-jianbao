Claude / Anthropic

Claude 平台 OpenTelemetry 追踪公开测试：托管 Agent、Messages API 与 SDK 可导出

Anthropic 宣布公测：把 Agent 回合、模型调用、工具与 MCP 调用以标准 OTel 轨迹送到 Grafana、Langfuse、Sentry 等，便于与业务日志同屏排障。

2026-10-15 Claude / Anthropic

Anthropic 于 10 月 14 日宣布，Claude 平台上的 OpenTelemetry（OTel）轨迹导出进入公开测试，覆盖 Claude Managed Agents、Messages API 与 Claude SDK。开发者在 Claude Console 配置导出目的地后，每个 Agent 回合、模型调用与工具使用会以标准 OTel 轨迹到达可观测性系统，并携带延迟、token 与轨迹 ID；SDK 侧可自动导出。若团队已把 Claude Code / Cowork 轨迹接到同一工具，平台上新建的 Agent 也可落在同一视图。

官方强调轨迹遵循 OpenTelemetry GenAI 语义约定，便于与其他厂商数据进同一仪表盘。文档按场景举例：在 Grafana Cloud、Honeycomb、Sentry、Splunk 旁路排障；用 Arize、Braintrust、Datadog、Langfuse、LangSmith、New Relic、PostHog 等把生产轨迹做成评测；用 Databricks Unity Gateway 做组织级用量与异常告警。轨迹也可发往任意接受标准 OTLP 的端点。工具与 MCP 服务器调用同样会出现在轨迹里。

多家客户引言强调「看得见才能改」：Foxglove 把轨迹与 PostHog 产品数据并排；Ramp 用 Reflect 扫 Langfuse 轨迹降 token、加速会话；财务类 Agent 则把模型调用与对账工作流放进 Grafana 同一时间线以备审计。功能仍为公测，Anthropic 未公布定价变更或全面可用时间表。对本窗读者：这是开发者可观测性能力，不是新聊天模型；与同窗选举防护长文分开成卡，避免混为一谈。

交叉核对以 Claude.com 官方文章与平台文档为准，Unite.AI、TokenPost 等转述与官方要点一致。后续需盯：是否默认导出提示全文、企业合规开关，以及公测转正式的时间。
