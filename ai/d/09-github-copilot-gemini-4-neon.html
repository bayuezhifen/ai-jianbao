GitHub Copilot 正式提供 Gemini 4 Neon

GitHub 宣布 Gemini 4 Neon 已在 Copilot 正式可用，面向智能体式编程、多步工具调用和知识工作。谷歌称其质量接近 Gemini 4 Carbon，但单次任务的 token 成本更低、开始应答更快。

2026-11-19 开发者工具

GitHub 在 11 月 18 日的变更日志中宣布，Gemini 4 Neon 已在 GitHub Copilot 中正式提供。官方把它定位为适合智能体式编程、多步工具调用和知识工作的模型。按照谷歌的说法，Neon 的质量接近 Gemini 4 Carbon，但完成同样任务消耗的 token 更少；与 Carbon 相比，它开始给出回应的速度更快，在编程任务里更少做未被要求的改动，也不那么容易对代码、工具或测试结果作出没有依据的断言。这些对比来自谷歌的自称，GitHub 的公告并没有附上自己的评测表，本报把它当作厂商口径，而不是已经由第三方复核的结论。

可用性方面，Neon 面向 Copilot 的 Pro+、Max、商业版和企业版用户，可在模型选择器里选用，覆盖 Visual Studio Code、Visual Studio、Copilot 命令行、编程智能体、Copilot 应用、github.com、GitHub 移动端，以及 JetBrains、Xcode 和 Eclipse。GitHub 写明会逐步推送，如果一时还看不到，可以稍后再查。计费按供应商目录价、在按量计费模式下结算。企业版和商业版管理员可以通过 Copilot 设置里的模型策略管理是否开放；在默认开启新模型的前提下，除非管理员关掉全局默认或单独关闭该模型，新模型会自动可用。

把这条放进“开发者工具”栏，是因为它改变的是 Copilot 里可选的模型菜单，而不是 Cursor 或其他编辑器自己的版本。昨日简报已经写过 Copilot 的浏览器操控公开预览，那是 11 月 17 日的变更，本期不再重复。Neon 的加入，意味着 GitHub 在自己的助手里继续同时接入多家前沿模型，并且明确把“少改不该改的地方、少说没有依据的话”当成卖点之一。这对在仓库里跑自动改动的团队更有实际意义，因为乱改和幻觉往往比模型“不够聪明”更麻烦。

尚未公开的信息包括：GitHub 或独立机构给出的对比评测、推送完成的时间表，以及在不同编辑器里是否同步到位。想试用的人应以 GitHub 文档中的模型与定价说明，以及自己工作区管理员的策略为准。本条只记录 18 日这则正式可用的公告。

对已经在用 Copilot 的团队来说，更实际的动作是先看自己的套餐是否在名单里，再由管理员确认模型策略没有关掉新模型，最后在编辑器的模型列表里核对是否出现 Neon。定价以 GitHub 的模型与价格文档为准，不同供应商的目录价并不相同，不宜把“更便宜”理解成 Copilot 订阅费本身下调。
