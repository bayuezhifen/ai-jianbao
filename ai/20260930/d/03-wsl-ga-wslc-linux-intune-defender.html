操作系统与桌面

微软宣布 WSL 容器正式 GA：wslc 原生跑 Linux 容器，Intune／Defender 可管

Windows 开发者博客：WSL containers 结束预览、全面可用；命令行 wslc／别名 container，并开放 Windows 应用调用容器的 API。企业侧可接 Intune 镜像白名单与 Defender 遥测。

2026-09-30 操作系统与桌面

晨报操作系统栏为空徽章，写到 iOS 补丁与 CoreGraphics 属窗外。本窗补上微软 9 月 29 日（上海时区已入 30 日）的正式稿：WSL 容器（WSL containers）结束预览、宣布一般可用。官方口径不是另起一套「虚拟机产品」，而是让开发者在 Windows 11 上直接构建、运行、部署 Linux 容器——终端执行 wsl --update 或安装最新 GitHub 发行版，即可使用 wslc.exe（及 container.exe 别名），并开放一套供原生 Windows 程序调用的容器 API。本地跑 AI 工作负载、把云侧容器化应用拉回本机调试，是文中点名的场景。

相对预览版，GA 补齐了日常运维缺口：容器重启、经 tar 进出拷贝文件、一眼看环境状态的系统信息、网络挂接与断开、事件流、健康检查、创建／运行时的挂载与停止超时（含无限等待）等；默认会话的存储路径也可改到指定盘。性能与网络上，官方称借助 virtiofs 等改进，从 Linux 环境访问 Windows 文件最高可约翻倍；并引入面向容器工作流的 consomme 网络模式，让流量经 Windows 主机转发，改善代理与企业策略兼容。路线图把 compose 列为下一优先：目标是现有 compose.yaml 少改甚至不改就能拉起。

企业治理是本条与「个人装个 Docker Desktop」的差别所在。Intune 可开关整个 WSL 容器功能，并用镜像仓库白名单限制只从批准源拉取；Microsoft Defender for Endpoint 既有的 WSL 插件扩展到容器内的进程、文件与网络活动，并回挂到 Windows 主机调查视图，避免两套安全流程。生态侧，VS Code Dev Containers、Aspire、社区 TUI 与桌面管理器等已陆续接 wslc。IT之家等中文报道同步提到 3.0.1 包装与内核 6.18 等细节，版本号以微软发行说明与 GitHub release 为准。

边界：不做公有云 IaaS／PaaS 专栏；不把英伟达 OpenShell 或「Windows PC 上的个人智能体」技术博文塞进本卡。苹果 CoreGraphics 零日见漏洞栏的 KEV 增量，不在操作系统产品卡里展开。对开发者，这是本机 Linux 容器工作流的正式化；对企业，关键看 Intune 与 Defender 策略是否跟得上启用节奏。

对习惯 Docker Desktop 或远程 Linux 开发机的人，GA 的意义是少一层「再装一套引擎」的摩擦，并把容器活动纳入 Windows 既有的安全与合规工具链。预览用户可直接升级验证命令是否齐全；尚未启用的团队，建议先在 Intune 里定白名单策略，再对开发机组放开，避免「先全开、再补治理」。
