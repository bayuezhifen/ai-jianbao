Vercel 淘汰长期静态凭证：Marketplace 11/30 打「Not secure」，2027-01 未支持安全认证将下架

Vercel 官方博客宣布推动机器间认证默认改为 OIDC 等短时身份令牌：Marketplace 集成若仍用长期密钥，2026-11-30 起标注 Not secure，2027-01 起不提供安全认证的厂商将从 Marketplace 下架。同步开源 OIDC UI（shadcn 注册表）并扩展 Connect / API / CLI 的 OIDC 能力。检索未见独立二报，本条以官方为主。

2026-10-22 身份与访问

Vercel CTO Malte Ubl 10 月 22 日发文 Death to long-lived static credentials：把「长期静态凭证」（API Key、数据库密码等无过期或极少轮换的密钥）比作 2010 年的明文 HTTP——标准已有（OAuth/OIDC/DBSC），但默认体验仍是贴密钥。文章强调：智能体拿到过宽权限密钥后，一旦泄露进仓库、被供应链读走或被提示注入骗出，攻击者可沿权限用到过期或吊销为止；轮换往往跨系统、成本极高。

对策轴心是 OIDC：由可信发行方签发短时签名令牌，接收方校验后再授权；被偷的令牌会自行过期。Vercel 侧已把 Blob、AI Gateway、Sandbox 等接到 OIDC，联邦自 2024 年 GA，可把部署身份换成 AWS/GCP/Azure 临时凭证。为降低接入摩擦，发布 OIDC UI（shadcn/ui 注册表），内含信任策略表单与服务端校验代码，覆盖 Vercel/GitHub/GitLab/Google/Bitbucket/AWS/Azure 等发行方。Vercel Connect 则让应用在运行时按用户与 scope 取提供商令牌，免存长期密钥。

Marketplace 硬期限：对调研的 1000+ SaaS 里仅约 8.4% 支持安全认证。仿照浏览器给 HTTP 打「Not secure」——2026 年 11 月 30 日起，Marketplace 上仍用长期密钥、未支持从 Vercel 到其服务的 OIDC 认证的厂商将显示 Not secure；2027 年 1 月起，不提供安全认证的将被下架。Vercel 自称 API 与自有原生集成也按同一标准执行。边界：检索未见权威二手专稿，细节以官方博客为准；「下架」针对 Marketplace 列表，不等于切断所有外部 API 密钥能力。
