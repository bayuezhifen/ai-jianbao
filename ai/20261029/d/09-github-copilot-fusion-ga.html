GitHub Copilot Fusion 正式可用：按任务自动路由编排多模型

GitHub 10 月 28 日 Changelog：Copilot Fusion 全面可用。开发者选 Fusion 与力度档，而不是每次手选模型；系统按任务路由与编排，管理员可限定可用模型池。

2026-10-29 开发者工具

Copilot Fusion 合并了 Project HydraFusion 的多模型编排与此前「自动选模」能力。模型选择器里选 Copilot Fusion，再选 Standard / High / Max 三档力度：日常编码、较难推理、最重任务。计费按实际调用到的各模型标准价；付费 Copilot 计划限时享模型费用 30% 折扣。

编排形态包括：单模型直接解；Cascade——省钱模型先起草，质检不过再升级；Critique——一模型起草、另一模型审、原稿模型改。GitHub 称在 Artificial Analysis Coding Agent Index 上，Fusion Max 约 60 分，距 Claude Code + Opus 5.5 Max 约两分，同时平均 API 成本、代币量与耗时更低（官方自述约一半成本/代币、约少 40% 时间）。

企业治理：Fusion 只使用企业/组织策略里启用的模型；管理员可单独禁某模型给 Fusion 用、而不必对所有人关掉该模型；也可把某一档 Fusion 设成托管默认。覆盖 VS Code、Copilot 应用、CLI 与 JetBrains；更多客户端「即将」。研究预览里开过 auto / HydraFusion 的用户会迁到对应 Fusion 档。

边界：这是路由层，不是 GitHub 自研新基座模型；分数与成本优势来自官方评测叙述，需用自家仓库复验。本栏是 Cursor 以外的开发者工具；Cursor 本窗无新主条。

交叉核对

  • 多方一致：GitHub Changelog GA；三档力度；按所用模型计费；管理员可控模型池。
  • 分歧：第三方对「半价跑出接近 Opus」的复现尚未铺开，暂以官方指数为准。
  • 待确认：折扣活动结束日；更多 IDE 客户端上线时间。
