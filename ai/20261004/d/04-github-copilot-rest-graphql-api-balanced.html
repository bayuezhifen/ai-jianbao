GitHub Copilot 代码评审开放 REST／GraphQL API，默认努力等级改为 Balanced

Changelog 10 月 2 日：可用官方 API 发起 Copilot 代码评审并按次指定努力等级；Balanced 成为默认（此前公告的切换自 9 月 28 日起生效）。昨晨主条写下架模型，本午补 API。

2026-10-04 开发者工具

对自动化流水线而言，这比「在网页上点一下评审」更关键：REST 与 GraphQL 均可请求 Copilot 代码评审，并可按次设置努力等级，便于脚本、工作流与内部工具把评审嵌进现有系统。Changelog 写明适用于 Copilot Pro、Pro+、Max、Business 与 Enterprise。官方文档仍建议把 `copilot-pull-request-reviewer[bot]` 当作评审方之一来发起请求。

默认努力等级改为 Balanced：GitHub 称此前已预告，自 2026 年 9 月 28 日起对新旧仓库与组织生效；若设置里显式选过 Lite，则保留 Lite。企业／组织／仓库／个人四级均可覆盖上级默认，配置入口在 AI controls 或 Copilot → Code review。按次覆盖适合「核心路径用更深、例行改动用更浅」的成本控制，而不是一刀切。

同日 Changelog 还有模型下架（Gemini 3.5／3.6 Flash、Kimi K2.7 Code、Claude Opus 4.7 等），昨晨已主条记录；10/3–10/4 无更新主条。本条只补「可编程发起评审」与默认等级切换，避免与下架卡重复。另有同日仓库安全公告评论 API 等条目，主题分散，不升列为本窗第二张开发者工具卡。

落地时注意三点：API 能发起评审，不等于替代人工对高危变更的终审；努力等级影响深度与成本，需按仓库风险校准；企业策略若强制 Lite／Balanced，应先在组织级写清，再让仓库覆盖，以免脚本与 UI 设置互相踩。
