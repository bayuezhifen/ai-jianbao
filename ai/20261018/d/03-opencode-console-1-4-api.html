（补录）OpenCode Console 遭入侵：约 1.4% 用户第三方 API 密钥或已暴露

官方称与「大规模蒸馏攻击」相关；受影响用户已邮件通知，须立刻在各云厂商控制台吊销密钥并核查异常用量。晨报漏收，午后补入。

2026-10-18 漏洞与勒索

开源编程智能体 OpenCode（Anomaly Innovations）于 UTC 10/17 约 18:08（上海已入 10/18 凌晨）发帖确认：前一夜发生与「large scale distillation attack」相关的安全事件，波及约 1.4% 的 OpenCode Console 用户；「If you did not get an email you were not impacted」，受影响者为曾在 Console 绑定外部模型提供商密钥的子集。邮件主题大致为「Action Required: Potential provider key breach」，称有人未授权访问正准备下线的遗留系统，工作区中保存的密钥「可能已暴露」。

公开后果先于官方声明出现：多名开发者在 X 上报告 OpenAI、Anthropic、Google 等账户出现异常扣费或限额，金额从数百到逾千美元不等（媒体转述、未逐笔公证）。Anthropic 工程师 Lydia Hallie 等称已协助吊销疑似受影响的 Claude API 密钥。Notebookcheck 等 10/17 晚至 10/18 早间跟进；The Latent、Techmeme 10/18 凌晨档仍将此事置于安全要闻。晨报约 08:20 未收本条，故午后按既往「漏收补录」惯例写入漏洞栏，不因事件起点略早于晨报而丢弃。

OpenCode 称事故仍在调查，细节有限，正与 Anthropic、OpenAI、Google 协同处置。公司把事件归入「蒸馏攻击」叙事——即借他人模型输出来训练/改进己方模型——但安全评论者指出：盗用 API 密钥造成账单损失，与「蒸馏」技术标签是否一一对应仍待更多取证。无论标签如何，对用户的动作清单是明确的：在各提供商控制台吊销并轮换密钥、更新依赖该密钥的应用、审查 10/16 起的用量与账单，并警惕钓鱼「官方补救」邮件。

对行业的提醒是：把第三方高权限密钥集中存进第三方 Console，等于把账单与配额暴露面外包；开源客户端再流行，付费托管层仍须按密钥保险库标准设防。OpenCode 是否赔偿、精确受害人数与攻击者身份，本窗均未官宣，简报不作臆测。
