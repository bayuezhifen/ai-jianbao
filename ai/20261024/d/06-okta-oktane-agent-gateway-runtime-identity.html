Okta Oktane 再谈 Agent Gateway：运行时校验「用户+代理」双身份，堵住糊涂代理人

SiliconANGLE 10 月 23 日晚更新 Oktane 现场综述：Okta 把身份从登录门禁推到代理调工具的运行时路径；Agent Gateway 要求凭证同时点名终端用户与代理。今晨身份栏为空，本窗补收。

2026-10-24 身份与访问

今晨身份与访问栏为空。本窗主条落在 Okta Oktane 期间被现场与官方材料反复强调的 Agent Gateway。SiliconANGLE/theCUBE 10 月 23 日晚间综述写明：随着代理跨应用调用工具，企业关心的不再只是「能不能登录」，而是「这次动作代表谁、被允许做什么」；Okta 产品与技术总裁 Ric Smith 称，公司正从非行内决策走向行内授权。

Okta 官方博客（产品页称 Agent Gateway 已随 Okta for AI Agents 提供）解释技术要点：传统 MCP 网关常用共享服务密钥或只能携带单一身份的 bearer token，容易出现「代理有权限、用户其实不该看」的糊涂代理人问题。Agent Gateway 按 RFC 8693 做令牌交换，要求每次调工具的凭证同时包含 subject（终端用户）与 actor（已注册代理）；网关按策略校验后，再向下游换取绑定同一用户的短时凭证，并留下可归因审计。Kill Switch 扩到网关、可吊销已签发令牌等能力，官方材料仍标为规划/分阶段，落地以控制台实际开关为准。

边界：不回炒更早的 Vercel OIDC、eMudhra 中级 CA 事件；不把 Blueprint Alliance 行业倡议写成已强制的合规标准。现场「多厂商谁说了算」的张力，SiliconANGLE 已点出，属开放问题。

  • 分歧：新闻稿可用性表曾写 Agent Gateway「计划 Q3 GA」，博客称现已可用——以控制台开通状态与客户经理口径为准。
