GitHub 应用进 Microsoft Teams：频道通知可 @GitHub 直接调查并开 PR

GitHub Changelog 10 月 23 日：Teams 里的新 GitHub 应用把通知与 Copilot 打通，议题报到频道后可用 @GitHub 让代理排查并创建拉取请求；旧版「GitHub notifications」可升级，遗留 GitHub 应用将于 11 月 16 日退役。

2026-10-24 开发者工具

相对已收的 GitHub Package Firewall 等供应链能力，本窗开发者工具主条落在「协作聊天里直接收工」。GitHub Changelog 10 月 23 日写道：Teams 里的新 GitHub 应用把通知与 Copilot 打通，帮助团队在不离开对话的情况下，把更新变成修复并更快合入代码。

官方给出的路径分三步：缺陷或议题通知进到频道、群聊或私聊；在对话里 @GitHub（合并应用里的提及名）触发调查与修复并创建拉取请求；团队在 PR 上审查、测试并合并。对已安装旧版「GitHub notifications」的租户，升级到最新版即可保留原有通知能力并叠上 Copilot。

迁移日程写得很硬：仍在用遗留 GitHub 应用的组织，该应用将改名「GitHub (deprecated)」并在 2026 年 11 月 16 日退役；需改装合并后的 GitHub 应用，并按提示连接 GitHub 账号、选择仓库。社区讨论区同步开放反馈。

同日外媒还报道 Agentic Autofix 对代码扫描告警的 GA 解读，但官方 changelog 显示该能力早在 10 月 15 日已一般可用，故不作为本窗「新发布」主条，以免回炒。Cursor 官方 Changelog 自 10 月 13 日后无本窗新条目，相关二手传闻不塞进本条。

边界：不把 Teams 内 @GitHub 写成可无人值守自动合并；审查与合并仍在人。企业策略、Copilot 计费与数据驻留以 GitHub Enterprise Cloud 既有开关为准。
