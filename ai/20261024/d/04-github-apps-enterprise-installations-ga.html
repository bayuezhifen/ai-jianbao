GitHub Apps 企业级安装正式可用：治理/安全/管理权限扩围，可更多替代经典 PAT

GitHub Changelog 10 月 23 日宣布企业账户安装 GitHub Apps 正式 GA，并扩大企业治理、安全与管理类 API/GraphQL 覆盖；今晨只收了 Copilot 进 Teams，本窗补这条。

2026-10-24 开发者工具

今晨开发者工具栏已收「GitHub 应用进 Microsoft Teams、频道通知可拉调查并开 PR」。同日 Changelog 还有一条更偏企业治理的更新，今晨未单列：企业级安装 GitHub Apps 正式可用。官方写明，可在更多企业与组织自动化里用 GitHub Apps 替代经典个人访问令牌（PAT），并补上一批此前缺口的权限。

新增与扩围权限按三类归纳：治理侧可管理企业级仓库策略与 ruleset、读取委托绕过请求；安全侧可配置双因素要求、校验域名、管理 IP 允许列表与企业访问限制；管理侧可更新企业资料、成员特权与跨企业仓库访问设置。文档表格还列出企业组织/仓库策略、bypass 请求、IP allowlist、可验证域名等对应的 REST/GraphQL 能力。这些更新亦将进入 GHES 3.24。

边界：企业安装只管企业账户本身，组织或仓库仍需另行安装才能拿到对应范围权限；企业安装令牌不能再收窄范围。不回炒今晨 Copilot×Teams，也不把「Public monitoring 分诊/有效性检查」与本条混写成同一产品——后者可另文，本窗主条落在企业 Apps GA。

交叉核对

  • 多方一致：GitHub Changelog 10/23「Enterprise installations for GitHub Apps generally available」；Docs「Installing a GitHub App on your enterprise」。
  • 分歧：无实质口径冲突；部分二手稿把同日多条 Changelog 揉成一条，本窗拆开只收企业 Apps。
  • 待确认：各企业现有经典 PAT 迁移清单与 GHES 3.24 落地节奏。
