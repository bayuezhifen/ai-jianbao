微软正式发布 .NET 11（标准支持期两年），.NET 8 与 9 于同一天结束支持

这是为期两年的 STS 版本，长期支持仍看 .NET 10。默认语言是 C# 15，.NET MAUI 改为默认使用 CoreCLR。同日还发布了 11 月安全服务更新；仍在使用 8 或 9 的项目需要迁到受支持的版本，才能继续拿到修复。

2026-11-10 语言 / 运行时 / 框架

微软开发博客在 2026 年 11 月 10 日 16:11（协调世界时）宣布正式发布 .NET 11，换算到上海是 11 月 11 日 0 时 11 分。同一时刻稍早一分钟，还发布了 11 月的 .NET 与 .NET Framework 安全服务更新。官方写道，今天宣布 .NET 11 发布。按支持政策，.NET 11 是标准支持期（STS）版本，支持两年；长期支持仍然看 .NET 10。Visual Studio Magazine 的戴维·拉梅尔和 Thurrott 当天都做了报道。11 月 10 日至 13 日正值 .NET Conf 2026，发布出现在大会首日。

默认语言版本是 C# 15，面向 net11.0。官方介绍的语言能力包括联合类型、封闭层次结构，以及扩展索引器和带标签的 break/continue。同一天还发布了 F# 11 的改进。工具链方面，SDK 默认启用面向本机的预编译（Native AOT）命令行宿主，MSBuild 服务器也会在多次命令行调用之间保持热身。ASP.NET Core 增加了异步校验，生成的接口文档默认采用 OpenAPI 3.2，并带来新的 Blazor 与 SignalR 能力；官方同时写明，Blazor 的人工智能组件和 Runtime Async 仍处于实验或预览阶段。.NET MAUI 则改为默认使用 CoreCLR 作为运行时。

需要立即面对的，是支持周期的切换。官方明确写道：.NET 8 与 .NET 9 于 2026 年 11 月 10 日结束支持，要继续拿到修复，须迁到仍受支持的版本。11 月服务更新覆盖 .NET 8、9、10、11，对应版本分别是 .NET 11.0.0（正式版已包含本月修复）、.NET 10.0.15、.NET 9.0.23 和 .NET 8.0.34。官方博文列出的漏洞包括：CVE-2026-114146（ASP.NET Core 权限提升，影响 8 至 11）、CVE-2026-109475（.NET 拒绝服务，8 至 11）、CVE-2026-105544（.NET 权限提升，8 至 11）、CVE-2026-114151、114152、118745、114158、114159（Visual Studio 远程代码执行，8 至 11）、CVE-2026-70175（ASP.NET Core 权限提升，8 至 11），以及多条 ASP.NET Core 的拒绝服务、信息泄露和安全功能绕过。具体哪些版本受哪一条影响，应以官方博文为准，这里不自行扩写。

有两条不能只升运行时。官方特别说明：CVE-2026-118747 需要单独更新 System.Formats.Cbor 这个 NuGet 包；在 .NET 9 这条产品线上，修复版本是 9.0.24，而不是 9.0.23，只安装运行时 9.0.23 并不能补上这个漏洞。另一条 CVE-2026-118741 影响 ASP.NET Core Identity 的脚手架和模板，只更新运行时并不能修好已经生成出来的代码。同一天还发布了 Visual Studio 2026 18.11.4，其中包含上述部分修复，以及 Git for Windows / MinGit 相关漏洞的补丁。仍在使用 .NET 8 或 9 的项目，应把迁移和本月补丁一并安排，不要只看到新版本发布、却把已结束支持的运行时留在生产环境里。标准支持期为两年，意味着 .NET 11 仍会在一段时间内收到修复；若生产环境更看重更长的支持窗口，官方给出的长期支持选项仍是 .NET 10。完整的漏洞说明和受影响版本，以 11 月服务更新博文为准。

交叉核对

  • 多方一致：微软开发博客、Visual Studio Magazine 与 Thurrott 均确认 .NET 11 于 11 月 10 日正式发布；它是为期两年的标准支持期版本，长期支持仍看 .NET 10；默认语言为 C# 15，.NET MAUI 改为默认使用 CoreCLR。官方同时写明 .NET 8 与 .NET 9 于同一天结束支持。
  • 服务更新：官方 11 月服务博文给出的版本为 .NET 11.0.0、10.0.15、9.0.23、8.0.34，并特别指出 CVE-2026-118747 在 .NET 9 线上须另升 System.Formats.Cbor 至 9.0.24，以及 CVE-2026-118741 不能只靠更新运行时修复已生成的脚手架代码。
  • 待确认：各 CVE 在 8 至 11 各版本上的精确受影响范围，应以官方服务博文中的表格为准，本条未自行补充未给出的分版本细节。
