npm 包 @subql/common 5.8.3 被植入窃密后门，安装或引用即触发

Web3 索引框架 SubQuery 的共享库 @subql/common 5.8.3 于 10/5 被发布成带窃密后门的恶意版本，安装和被引用时都会触发；它会搜刮开发机与 CI 上的各类凭据，还会试图在受害者其他仓库植入窃取 secrets 的工作流。

2026-10-06 开发者工具（IDE、CI、包管理，Cursor 以外）

10 月 5 日，StepSecurity 的自动包分析系统把 npm 上的 @subql/common 5.8.3 标为可疑。调查确认，这个版本藏有能窃取凭据并提供远程 shell 的载荷：安装时（postinstall 脚本）和被 import 时都会启动，因此只禁用安装脚本不够。GitHub 安全公告 GHSA-9333-3c4x-x3h5、OSV 的 MAL-2026-17571 已收录，亚马逊 Inspector 也独立确认了恶意代码。

发布过程很有代表性。UTC 11:23，有人在官方仓库建了临时分支，提交把发布工作流换成一个「红队金丝雀（无害）」版本，发布测试包 5.8.3-onf-rt1 后删掉分支；11:52 又用同名分支提交「[release] 5.8.3」，在构建之后、发布之前插入一步：从外部域名 ci-artifacts.dev 下载压缩包覆盖 packages/common，没有任何哈希或签名校验；11:56 带载荷的 5.8.3 上了 npm。提交署名对应一位维护者账号但没有签名，StepSecurity 强调这只能说明是哪个账号，不能断定是谁、是否获授权；main 分支也没有合入恶意改动。

载荷经过三层混淆，会读取 .npmrc、.env、AWS 凭据、SSH 密钥、kubeconfig、钱包路径，以及 .claude.json 等 AI 工具配置；在 Linux 版 GitHub Actions 运行器上用 sudo 读取 Runner.Worker 进程内存找密钥；尝试横扫 17 个区域的 AWS Secrets Manager 和 SSM 参数、集群内的 Kubernetes secret 和 Vault。拿到带 workflow 权限的 GitHub 令牌后，它会在可推送的仓库里建一个伪装成 Dependabot 的分支和名为 CodeQL 的工作流，把全部 secrets 打包成构件取走再删痕迹。数据加密后发往 ci-artifacts.dev，另有远程命令通道；检测到俄语环境会直接退出。

波及面不只这一个包。@subql/cli、@subql/node-core 等用 ~5.8.2、^5.8.2 这类版本范围依赖它，父包不发新版也会解析到 5.8.3。StepSecurity 按 10/5 的快照检查了 77 个 @subql 包，有 19 个最新版存在通往 5.8.3 的依赖路径。该版本随后已从 npm 下架。

处置建议：在锁文件和传递依赖中排除 5.8.3，固定到 5.8.2 等已核实版本；装过或引用过的主机和 CI 运行器先隔离取证，再用可信镜像重建——卸载停不掉已分离的后台进程；轮换所有可能暴露的凭据；封锁 ci-artifacts.dev，排查名为 codeql_analysis.yml 的工作流和 dependabot/github_actions/format/setup-formatter 分支。GitHub 公告措辞更重：装过这个包的机器应视为完全失陷。

这次攻击没有改源代码，而是在 CI 构建和发布之间替换产物，npm 的来源证明照样生成，源映射也被刻意删减。只审源码或源映射的做法会漏掉这类问题。

交叉核对

  • 多方一致：StepSecurity 与 OSV（汇总 GitHub 与亚马逊 Inspector）对受影响版本 5.8.3、安装加引用双重触发、隐藏加载器的描述一致。
  • 待确认：维护者账号是被盗还是内部人员所为；StepSecurity 称尚未观察到有受害仓库真的被注入工作流。
