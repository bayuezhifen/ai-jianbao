GitHub Package Firewall 公测：拦在 CI/智能体与上游包仓库之间（先支持 npm）

GitHub 于 10 月 20 日（21 日改写澄清）推出 Package Firewall 公测：挡在端点、内部源与上游包仓库之间，检查元数据与下载；面向 GitHub Enterprise Cloud，预览期免费，目前仅 npm。

2026-10-22 开发者工具

今晨开发者工具主条是 LiteLLM 1.107.0 供应链投毒；本窗补一条平台侧防线。GitHub 称近期大量恶意软件卡在「安装时」下手，CI 与编码智能体尤其危险——无人值守就会装依赖。Package Firewall 让管理员先定策略（可配置冷却期、对照 Advisory Database 查恶意/漏洞、供应链校验如证明降级等），再让智能体与 CI 主机改走防火墙 URL，而不是直连上游；误拦可走类似 Advanced Security 的例外申请。

范围与商业：公测对 GitHub Enterprise Cloud（含数据驻留版）开放，预览期免费，GA 后拟按用量计费（类似 Actions）。当前生态只支持 npm。官方文档说明如何在企业策略与 .npmrc 中指向防火墙端点。把这条与今晨 LiteLLM 事件并读，可以看出「安装时策略门」正在从倡议变成大厂托管能力；它不替代钉版本、私有镜像与人工审计，但能把一批已知坏包挡在跑起来之前。

边界：不回炒 Clairic、今晨 LiteLLM 投毒细节；也不把「仅 npm」夸成全语言供应链银弹。其他包生态何时接入、误拦率与例外 SLA，仍待公测反馈。

交叉核对

  • 多方一致：GitHub Changelog 官宣公测；Docs 有配置指南；仅 npm；Enterprise Cloud 预览免费。
  • 分歧：部分媒体标题写成「在 npm 与 CI 之间竖防火墙」——准确，但易忽略策略可配与例外流程。
  • 待确认：GA 计价细则、PyPI/Maven 等后续生态时间表。
