漏洞与勒索

OpenJDK 被披露 Java4Shell 漏洞，Oracle 已随 11 月补丁修复，CISA 呼吁立即更新

安全公司 Calif 17 日披露 OpenJDK 硬件加速 Base64 解码中的内存损坏漏洞 CVE-2026-114938，并称可在部分企业应用的默认配置下造成远程代码执行。Oracle 已在当天的季度补丁中修复，CISA 呼吁立即安装。

2026-11-18 漏洞与勒索

安全公司 Calif 17 日披露，OpenJDK 在部分 x86-64 处理器上使用的硬件加速 Base64 解码功能存在内存损坏漏洞，编号为 CVE-2026-114938，并被称作 Java4Shell。BleepingComputer 当天的报道写道，研究人员认为该问题影响 OpenJDK 17.0.6 及之后版本，以及据此构建的多家发行版，包括 Oracle Java SE、Amazon Corretto、Eclipse Temurin、Microsoft Build of OpenJDK、Azul Zulu 和红帽 OpenJDK。Calif 给出的 CVSS 4.0 评分为 9.2（严重），Oracle 用 CVSS 3.1 给出的评分是 8.1（高）。漏洞本身针对的是受支持处理器上那条加速解码路径，并不是所有 Java 程序、所有 CPU 都会走到同一段代码。

Calif 称，他们已在多种广泛使用的企业应用默认配置下完成远程代码执行验证。被点名的未认证场景包括 Keycloak、Atlassian Jira、Atlassian Confluence、JFrog Artifactory、Jenkins 和 PingFederate；需要认证的场景则包括 Apache Kafka Broker、Apache Solr、Elasticsearch、Gerrit 和 Spinnaker。研究人员也强调，并不存在一条对所有应用通用的利用方式，攻击者必须为具体应用找到把特制数据送到脆弱解码路径的办法。本报只记录这些已经被公开点名的影响面，不复述具体构造或验证步骤。

补丁方面，Oracle 在 17 日的季度关键安全更新中修复了该漏洞。OpenJDK 方面，窗口内可见的修复版本包括 17.0.21.1、21.0.13.1、25.0.5.1 和 27.0.1.1。需要单独写明的是：同期还有 Java SE 11 和 8 的安全更新，但 Java 8 与 11 不受 CVE-2026-114938 这条漏洞影响。美国网络安全与基础设施安全局同一天发布警报，敦促机构立即安装 Oracle 的 11 月补丁。若暂时无法升级运行时，Calif 建议以关闭该硬件加速解码路径作为临时缓解，这只是权宜办法，不能替代更新。

这是本期漏洞栏最值得优先处理的一条，原因很直接：影响的是大量企业应用共同依赖的 Java 运行时，而不是某一家的单独产品。CISA 的警报和 Oracle、OpenJDK 的补丁同日出现，说明厂商和政府侧都把它当成需要马上处理的问题。是否已经出现大规模在野攻击，公开材料里没有写成既成事实，本报也不作这样的断言。运维和开发团队应当先核对自己的发行版和版本号，再决定是更新运行时还是先加上临时缓解。

对无法立刻升级的系统，临时关闭硬件加速解码只是权宜办法，且只覆盖这条特定路径，并不处理 11 月补丁包里的其他修复。企业还应当向应用供应商确认：自己使用的 Jenkins、Jira 或其他产品，是否需要在更新 Java 运行时之外再打应用层补丁。公开报道没有把“已经出现大规模攻击”写成事实，但把更新拖到方便的维护窗口，显然和 CISA 的紧急语气不符。

交叉核对

  • 一致处：CVE-2026-114938、17 日披露与修补、影响 OpenJDK 17.0.6 及之后和多家发行版、CISA 呼吁立即打补丁，均可在 BleepingComputer、CISA 警报和 OpenJDK/Oracle 说明中交叉核对。
  • 评分差异：Calif 给出 CVSS 4.0 的 9.2，Oracle 给出 CVSS 3.1 的 8.1，应并存，不单取较高的那个写成“官方评级”。
  • 限制：本报不复述利用构造。Java 8 与 11 不受该条影响，但它们仍可能包含 11 月补丁包里的其他修复。
  • 待确认：是否出现大规模在野利用，以及各 Linux 发行版和云镜像跟进修复的时间。
