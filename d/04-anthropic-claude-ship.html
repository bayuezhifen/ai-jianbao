Claude / Anthropic

Anthropic 推出 Claude Ship，可按团队策略审核、修复并批准拉取请求

Anthropic 11 月 23 日宣布推出 Claude Ship。套件里，代码审查已正式可用；负责处理失败检查、合并冲突和审查意见的 PR Steward，以及可按仓库策略批准变更的 Claude Approvals，目前仍是测试版，面向 Claude 团队版与企业版、托管在 GitHub 上的仓库开放。

2026-11-24 Claude / Anthropic

Anthropic 在官网文章中推出了名为 Claude Ship 的工作流。TechCrunch 标注的发布时间是太平洋时间 11 月 23 日下午 2 时 05 分，折合上海时间 24 日凌晨 6 时 05 分，落在本窗口内。《维尔格》和路透社当天也作了报道。公司要解决的问题很直接：越来越多的代码由智能体写出之后，审查和合并反而成了瓶颈。Anthropic 自己的说法是，在 Claude Code 团队内部，大部分代码已由 Claude 编写，他们希望拉取请求提交之后的步骤也能同样快。

Claude Ship 并不是单一按钮，而是三件套。代码审查已经正式可用，用来给拉取请求找问题。PR Steward 还在测试：它处理持续集成失败、合并冲突，以及代码审查提出的意见，并在每次推送后说明改了什么、必要时如何回退。最引起外界注意的是同样处于测试阶段的 Claude Approvals——团队把批准策略写成仓库里的一份文件，审批过程可以参考代码审查结论或公司自己的分类器，策略本身用自然语言书写。也就是说，在策略允许的范围内，常规变更可以由智能体批准，而不必每一笔都等人点头。

Anthropic 把控制权留在团队手里，这一点在官方说明和 TechCrunch 的转述里是一致的。功能先向 Claude 团队版和企业版开放，而且针对的是 GitHub 上的仓库。因为批准能力仍是测试版，公司建议先用只观察、不真正合并的模式跑一段时间，也可以先只开一个仓库，并设置月度花费上限。团队仍可决定它在哪里运行、审查用快速、标准还是深入档，以及哪些变更必须交给人来决定。开发者也可以在 Claude Code 里使用 /ship 命令。

这套产品的意义，不在于「人工智能又会写代码了」，而在于它把批准权写进了可检查的策略文件。写代码的速度上去之后，若是每一笔改动仍要等人看完，瓶颈只是后移，并没有消失；可如果批准也交给模型，出错的责任和回滚路径就必须事先约定清楚。Anthropic 没有宣称可以取消人工把关，相反，它把「先观察、再放开」写成了建议步骤。试点客户的反馈也强调，人仍然留在环节里，只是把时间更多地用在真正需要判断的改动上。

眼下能核对住的是产品形态和开放范围，而不是它在各家公司里已经替人签了多少单。测试版意味着策略冲突、误批准和费用控制都还需要时间检验。本窗口没有在官网上核到更靠后的正式转正时间表。对已经在用 Claude 写代码的团队，这是一条可以按仓库逐步打开的新能力；对还没有把审查流程写成明确规则的团队，先补那份策略文件，可能比立刻打开自动批准更要紧。
