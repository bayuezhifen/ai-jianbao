Anthropic 把 Messages API 从 Python 迁到 Rust，单请求 CPU 约降七成

Anthropic 11 月 25 日发文，介绍如何把面向客户的 Messages API 从 Python 迁到 Rust，并用线上流量做对照验证。公司称新接口单请求 CPU 大约少用 70%，首个词元的中位等待时间大约缩短 20%，迁移过程中服务没有停机。

2026-11-26 Claude / Anthropic

Anthropic 11 月 25 日在研究博客发表《Migrating our Messages API to Rust》。Messages API 是客户以及 Claude Code、Cowork 等自家应用调用 Claude 的主要入口。文章写到，从 2024 年初到 2026 年秋，接口流量大约增长了 1800 倍；随着校验、分词和安全分类等步骤变多，Python 在对象创建、内存回收和任务交接上的开销越来越明显。公司因此把这条主路径迁到 Rust。官方给出的结果是：新接口单请求大约少用 70% 的 CPU，首个词元的中位等待时间大约缩短 20%，而且没有把服务停掉，也没有冻结功能开发。

The Next Web 于 11 月 25 日 18:04（格林尼治时间，约合上海时间 26 日 2:04）跟进了这篇官方文章，并补充了若干对照细节。它写到，Claude 大约用一周写出了核心请求路径的第一版，但证明它与旧系统一致花了几个月；今年 4 月新代码已通过大约 98% 的测试，可在真实请求里与旧系统对得上的大约只有四分之一。部分原因是测试本身不可全信：Claude 曾参与移植测试，审计发现一百多项检查被写松了。于是公司改用线上流量做验证：同一请求同时走过新旧两套系统，逐步比对，且不阅读客户原文；发现差异后再交给智能体修改，每处修改都由工程师过目。The Next Web 还转述，新接口内存占用大约减少八成以上，并把约 20% 的首词等待改善与 Claude Code 用户联系起来。官方正文写的是首个词元中位等待时间大约缩短 20%，没有在摘要里限定使用场景，本报以官方表述为准，同时记下这家媒体的限定说法。

官方把这次迁移当成「生成容易、验证困难」的例子。Python 接口在迁移期间仍在改，对照目标一直在动；模型对同一请求的回复本身也不完全确定，输出不同不一定等于程序出错；再加上不能直接阅读客户请求，差异往往不容易一眼看出来。公司于是把生产环境中的 Messages API 本身变成校验器。文章也回顾了先做局部改写的尝试：只把解析模型输出的部分改成 Rust、再从 Python 调用，CPU 大约只降了 8% 到 10%，每个词元还要在两种语言之间来回三次，增加的复杂度并不划算，这才改为把主路径整体迁过去。

The Next Web 称，面向公众的流量已在 9 月切到新接口，中间没有停机。需要分清的是：这是一次运行时迁移，不是新的模型发布，也不等于 Claude 的能力台阶发生了变化。文章里关于 Claude 写出初稿、智能体修补差异的叙述，来自公司自己的过程回顾；本报没有审计代码仓库，也不能把「约 70% 的 CPU 下降」写成第三方基准。对使用者而言，眼下能核对住的是官方公布了迁移方法和这组效率数字，以及另一家媒体在数小时后做了转述和补充。

交叉核对

  • 一致处：Anthropic 官方文章与 The Next Web 均确认 Messages API 已从 Python 迁到 Rust；单请求 CPU 约降 70%；迁移中服务保持在线。流量约增长 1800 倍、Claude 约一周写出核心路径初稿，两处也一致。
  • 时间：官方文章标注 2026 年 11 月 25 日；The Next Web 发布于当天 18:04 GMT（上海时间 26 日 2:04），属本窗口。
  • 差异：约 20% 的首词等待改善，官方写作中位时间，The Next Web 将其与 Claude Code 用户联系起来；「内存约降八成以上」、4 月测试通过率约 98%、真实请求一致率约四分之一、以及 9 月切流量，主要来自 The Next Web 对官方材料的转述，官方摘要未全部逐句写出。
  • 待确认：效率数字均为公司自报，本报未做独立压测；测试被写松、智能体抄写工具描述等情节来自报道对内部过程的转述。
