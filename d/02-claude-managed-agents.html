Claude Managed Agents 动态工作流进入公开测试

Anthropic 平台发布说明显示：Managed Agents 现可让主智能体编写分阶段、多智能体工作流，在后台跑完再合并结果。这是编排能力上的正式产品节点，而非又一则模型行为通报。

2026-10-10 Claude / Anthropic

Anthropic Claude Platform 发布说明在 2026-10-09 写入：Claude Managed Agents 现可使用动态工作流（dynamic workflows），目前为公开测试，需带上 `managed-agents-2026-04-01` beta 头。开启方式是把智能体的 `multiagent` 设为 `{"type": "multiagent_20261001", "workflows": {"type": "enabled"}}`。主会话仍可继续交互；工作流作为后台 `workflow_run` 执行，进度通过会话事件流里的 `workflow_run.*` 事件跟踪。

按官方文档描述，面对「审查数百份文档」这类可拆分任务，主智能体可以先写出一份工作流程序：分阶段拉起多个子智能体，再在收尾阶段合并结果。The Decoder 二次报道补充了 Anthropic 内部测例口径——在约 11.6 万行代码、预埋 70 个缺陷的仓库里，单智能体单次大约揪出 14–27 个，动态工作流则能稳定摸到约 66 个。这类数字属于厂商自测，外推到任意代码库仍要谨慎，但方向清楚：厂商在推销「多智能体并行」时，开始愿意给出可核对的对比实验，而不只是概念演示。

成本与滥用风险同样被点到。OpenAI 侧工程师近期公开批评「智能体蜂群浪费 token」；Anthropic 文档则提醒动态工作流可能消耗大量 token，建议从小规模起步。产品上，这与晨报已收的「非预期模型行为、切断内部评测公网」是两条线：一条是评测安全与对齐披露，一条是面向客户的编排 API。白宫超级智能部队随后要求事故立即披露，见同期「隐私与监管」条，不在此展开。

同窗周边：ClaudeDevs 称 Claude Code Projects 候补名单上的 Pro/Max 用户已放行，仍属公开测试、尚未进 Team/Enterprise。Projects 是「一个协调会话拉起多条云端线程」的产品面，与 Managed Agents 动态工作流同属多智能体编排，但入口与计费平面不同，本期以官方平台发布说明的 Dynamic Workflows 为主卡。
