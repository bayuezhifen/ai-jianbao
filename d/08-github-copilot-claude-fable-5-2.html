GitHub Copilot 上线 Claude Fable 5.2

GitHub 周一把 Anthropic 当天发布的 Claude Fable 5.2 接到 Copilot 的模型选择器里，覆盖 VS Code、JetBrains 和命令行等多个入口。企业管理员默认关闭，并且必须接受 Anthropic 为安全分类器保留数据。

2026-11-09 开发者工具（IDE、CI、包管理，Cursor以外）

GitHub 在 11 月 9 日的更新日志里宣布，Claude Fable 5.2 已在 GitHub Copilot 中正式可用，面向需要跨大型代码库做复杂、多步编程任务的用户。日志称，早期测试里它比 Claude Fable 5.1 解决了更多任务，用的步骤和工具调用也更少，并完成过一些旧模型没做出来的难题。计费按供应商目录价、走用量计费，具体数字指向 Copilot 的模型与定价说明。

可用范围写得很宽：Copilot Pro+、Max、Business 和 Enterprise 用户可以在模型选择器里看到它，入口包括 Visual Studio Code、Visual Studio、Copilot 命令行、编程智能体、Copilot 应用、github.com、iOS 与 Android 上的 GitHub Mobile，以及 JetBrains 集成开发环境、Xcode 和 Eclipse。GitHub 提醒推送是逐步展开的，如果暂时看不见，过几天再看。对企业来说有一道明确的闸门：Business 和 Enterprise 的管理员必须在 Copilot 设置里打开 “Claude Fable 5.2” 策略，该策略默认关闭。

比“能不能选到这款模型”更需要注意的，是数据留存。日志写明，Fable 5.2 默认要求保留数据，以便 Anthropic 运行用于发现有害用途的安全分类器；保留的提示词和输出不会用来训练 Anthropic 的模型。其他 Claude 模型——除了 Fable 5、Fable 5.1 和 Fable 5.2——仍按零数据留存运作。打开上述策略，就等于承认这一要求；不打开，组织里就没有这款模型。

对部分符合条件的企业，GitHub 提供了有时限的例外：在日历年结束前，可以继续按零数据留存使用 Fable 5、5.1 和 5.2，以便 Anthropic 推开 Enterprise Frontier Safeguards。那套机制打算在客户自己控制的存储和密钥上做自动安全监测。过了这个窗口，继续使用这些模型将需要接入该机制。是否符合例外资格，要问 GitHub 客户经理，技术支持无法查询或开通；即便批下来，也不会自动打开模型，管理员仍须再去打开策略。

把这则更新和 Anthropic 自己的发布放到一起看，Fable 5.2 从第一天起就不只出现在 Claude 官方接口里，也直接进了相当一部分开发者每天打开的编辑器。对已经在 Copilot 里用 Opus 或 Sonnet 做日常补全的人，它更像是一个需要管理员点头、专门留给难题的更高档位，而不是默认模型被整体换掉。代价是企业安全团队必须在“用更新的模型”和“接受为分类器留存提示词”之间做一次书面选择。这与 Anthropic 官网把企业零数据留存绑到 Enterprise Frontier Safeguards 的说法是对齐的，并不是 GitHub 单方面加码。

交叉核对

  • GitHub 官方更新日志是本条唯一的产品说明来源，发布日期为 2026 年 11 月 9 日，与 Anthropic 发布 Fable 5.2 为同一天。
  • 与 Anthropic 官网交叉：两者都把强大的 Fable 模型与安全监测、数据留存联系在一起，并把企业零数据留存指向仍在推开的 Enterprise Frontier Safeguards。
  • 可用性、默认关闭的企业策略、分类器留存、年终前有时限的零数据留存例外，均直接来自 GitHub 日志，未见相反报道。
  • 待确认：“比 5.1 解决更多任务、步骤更少”目前是 GitHub 的早期测试陈述，没有附上公开题目集或对照表。
