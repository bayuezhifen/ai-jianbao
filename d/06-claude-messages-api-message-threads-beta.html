Claude / Anthropic

Claude Messages API 推出 message threads 公测：长会话少传历史、首 token 更快

Anthropic 11 月 2 日称 Messages API 的 message threads 已公测：首轮传完整对话，之后只传新增消息；多数 Claude Code 用户默认开启，50 万–100 万 token 请求中位 TTFT 约降 35%。

2026-11-02 Claude / Anthropic

Anthropic 于 2026 年 11 月 2 日通过 Claude 资源中心宣布：Messages API 新增 message threads，并已进入公测。长程智能体（尤其编程代理）以往每一轮都要把整段对话与工具结果重新提交；上下文到数十万乃至近百万 token 时，仅重传就会拖长「首个 token 时间」（TTFT）。开启线程后，首轮仍提交完整对话并创建 thread，后续请求只带新增消息与上一轮响应 ID；官方称多数 Claude Code 用户已默认走线程，在约 50 万至 100 万 token 的请求上，中位 TTFT 约下降 35%。

实现边界写得很清楚：线程驻留内存、加密且不落盘，距上一请求约 5 分钟无活动即过期，客户端需自行保留完整对话以便重建；Claude 每轮仍会读完整上下文，因此计费 token 与现有速率限制不变——省的是等待，不是账单。适用场景包括长程编程代理、带截图的 computer use、以及文档/图片很重的工作流。平台覆盖原生 Claude Platform，以及 AWS、Microsoft Foundry 与 Google Cloud 上由 Anthropic 托管的 Claude 模型。

The Next Web 等二次报道补充：开发者通过请求里的 thread 参数创建/继续；公测覆盖各 Claude 型号；线程不适用于零数据保留或 HIPAA 等特殊合规配置。平台文档侧亦给出 beta 头与 create/continue 形态说明。对代理框架作者来说，这是延迟路径上的基础设施改动，需要处理 404（线程过期）后的全量重传，并继续自管会话持久化。

读产品新闻时把它和「降价」分开：Anthropic 强调价格与限速不变，此前缓存降价才是成本侧动作。若你的代理本就短会话，收益有限；真正吃到红利的是工具轮次极多、历史动辄数十万 token 的长跑任务。是否全量默认、各云厂商上线节奏，仍以控制台与发布说明为准。

交叉核对

  • 多方一致：11-02 前后公测；首轮全量、后续只传增量；约 5 分钟过期；TTFT 在超长请求上约降 35%；token 计费不变；多云可用。
  • 分歧：官方文章侧重 Claude Code 默认开启与场景清单；TNW 更强调「省时间不省钱」与不合规特殊保留套餐。
