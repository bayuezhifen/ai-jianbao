Windows 11 十一月累积更新 KB5132061 部分电脑装不上，微软支持文档仍写暂无已知问题

11 日的补丁发布后，有用户报告 KB5132061 安装失败，常见错误码包括 0x800F0993、0x800F0989 和 0x80070306。到《寄存器》截稿时，微软支持文档仍写暂未发现此更新的已知问题。

2026-11-11 操作系统与桌面

微软在 10 日的补丁星期二推送了 Windows 11 累积更新 KB5132061。今晨简报已经写过这次星期二本身，以及 Windows 11 23H2 企业版和教育版以此为最后一次月度更新，那些内容不再重复。11 日下午到晚上新出现的，是一部分电脑根本装不上这次更新。《寄存器》在 11 日 14:55 协调世界时（上海时间 22:55）报道，用户遇到的错误码包括 0x800F0993 和 0x800F0989。Windows Latest 还记录到 0x80070306，以及少数 0x800F0922，并说更新有时会走到 99% 然后失败，再试也不前进。

这次更新对应的版本号，Windows Latest 写的是：Windows 11 26H2 来到内部版本 26300.9974，25H2 来到 26200.9974。它还提到，因为还有待处理的安全启动证书更新，安装过程可能需要两次或更多次重启。这些是安装过程上的背景，本身并不等于故障。真正的问题是：一部分设备在下载或安装阶段就停住了，即使用微软更新目录里的独立安装包，也有人照样失败。

社区里流传较广的一个办法，是关掉 Windows 沙盒再重启、重试。ElevenForum 上有用户提出这个方向，Windows Latest 也记录到，有人在安装日志里看到与沙盒相关的文件缺失或「重建容器基本映像失败」，关掉沙盒后更新才装上。需要同时写上反例：也有人并没有开启沙盒，却遇到同样的错误；还有人无论沙盒状态如何，都要靠部署映像服务与管理工具检查、手动下载更新，或反复重启之后才通过。因此，把沙盒说成「唯一原因」并不准确，它只是一部分人有效的排查步骤。

更关键的是微软官方此刻怎么说。《寄存器》写到，微软当时没有列出该更新的已知问题，也还没有对此发表说明，媒体已向公司求证。Windows Latest 转述支持文档的原话，仍是公司「目前未发现此更新存在问题」。该站同时说，有人告诉他们，微软内部已经知道这些投诉并在查原因，包括沙盒是否有关。这后一句来自该站的不具名转述，不能当成微软已经发布的事故通告。在支持文档改口、或微软发布已知问题说明之前，稳妥的表述仍是：用户端故障报道已经不少，官方文档却还写着暂无已知问题。

对还没装上这次更新的人来说，实用建议也很有限：先看自己是否开了沙盒，关掉后再试；不行再尝试官方目录中的独立安装包，或按微软提供的更新组件重置步骤处理。Windows Latest 还提到设置里「通过 Windows 更新修复问题」这一选项，会重装当前版本并保留应用和文件，这是更重的一步，只有其他办法都失败时才值得考虑。因为这是一次包含大量安全修复的月度更新，拖着不装也有风险。最终仍要等微软给出正式的原因说明或修订包，社区办法不能代替官方修复。

交叉核对

  • 多方一致：《寄存器》和 Windows Latest 都记录到 KB5132061 在部分设备上安装失败，并出现 0x800F0993、0x800F0989 等错误；两家都写到有人通过关闭 Windows 沙盒后装上，但也都提到并非所有失败案例都能这样解释。
  • 官方口径：到《寄存器》截稿时，微软支持文档仍写暂未发现该更新的已知问题，公司没有公开发表说明。Windows Latest 关于「微软正在调查」的说法来自该站不具名消息，不能当作官方声明。
  • 与今晨衔接：今晨已报道十一月补丁星期二本身，本条只写随后出现的安装失败，不把补丁清单再讲一遍。
